# 视频链接解析服务验收记录（2026-09-27）

## LEAPERone 历史实测（已停用）

2026-10-06：已删除该服务的接口实现、配置示例和回退逻辑。以下仅保留历史验收事实，不代表当前服务配置。

使用账号 API Key 和服务商文档列出的公开视频测试，不记录密钥或临时媒体 URL：

| 平台 | 结果 |
| --- | --- |
| 抖音 | HTTP 200，返回 4 条视频流；其中一条 MP4 链接的 Range 请求返回 206，可读取 1 KB 视频数据。 |
| YouTube | 官方示例与另一公开视频均返回 HTTP 404。 |
| Bilibili | 官方示例曾返回 HTTP 400；后续返回 HTTP 200，但 `videos`、`audios` 均为空。 |
| TikTok | 官方示例返回 HTTP 400，提示请求失败。 |

结论：LEAPERone 的抖音解析可用，但这次测试无法证明其满足项目的五平台承诺。不能将 200 空结果计为成功，也不能仅凭单个平台失败断言服务整体停用。

## EasyDown 实测

EasyDown 适配器按其[统一解析接口](https://docs.easydown.org/en/api/common)接入，现为唯一的视频链接解析服务；必须设置 `EASYDOWN_API_KEY`，未配置时明确报错。媒体流的公开下载请求头会传给 FFmpeg Worker，API Token 不会传给 Worker。

使用账号 Token 对三个公开视频各调用一次统一解析接口，未记录密钥或临时媒体 URL：

| 平台 | 结果 |
| --- | --- |
| 抖音 | HTTP 200，返回 20 条视频流、2 条音频流；返回的视频流标记为含音频。未额外请求视频文件。 |
| Bilibili | HTTP 200，返回 6 条视频流、3 条音频流；一条 MP4 视频流使用返回的 `Referer` 后，Range 请求返回 206，可读取 1 KB。 |
| YouTube | HTTP 200，返回 24 条视频流、6 条音频流；选择的有声 MP4 下载请求从本机失败。本机对该 `googlevideo.com` 主机的 DNS 解析成功，但 TLS 连接超时，不能确定 Worker 是否也受影响。 |

随后使用开发桶 `promptlensdev` 和本地 FFmpeg Worker 继续验收；支付定时任务已从测试 Worker 进程禁用，未触碰生产桶：

| 平台 | EasyDown 解析与媒体链路 |
| --- | --- |
| TikTok | 官方示例解析成功：18 条视频流，22 秒，实扣 1 积分。本机 Worker 下载所选视频流失败，底层为连接 TikTok CDN 超时；其他几个 TikTok CDN 域名从本机也超时。尚不能判断部署环境是否可访问，更不能算端到端通过。 |
| Bilibili | 官方示例解析成功，实扣 1 积分。Worker 下载独立视频与音频并合并，写入开发桶；公开 R2 URL 可读，自动拆出 4 个镜头。 |
| 抖音 | 公开短链接解析成功，实扣 1 积分。Worker 下载并写入开发桶；公开 R2 URL 可读，自动拆出 3 个镜头。供应商标记时长 10 秒，Worker 检测时长约 13.14 秒，后续流程应以 Worker 实测为准。 |

另用约 1.1 MB 的公开测试 MP4 验证了 Worker 下载、开发桶入库、公开读取及拆镜，不把这项通用素材测试冒充 TikTok 成功。当前 EasyDown 账户最后一次响应显示余额 2 积分；本轮没有继续重试 TikTok。以上只验证了媒体解析、入库和拆镜，尚未完成真实登录用户从页面提交到模型分析、报价和结算的端到端验收。仅看到本地开发桶配置，未确认远程 Worker 的存储桶归属，因此没有向远程 Worker 发送测试素材。

产品暂定只支持 TikTok、抖音、Bilibili；YouTube 因单次解析成本决定不支持，X 暂不纳入当前范围。TikTok 下载未通过前不能宣布三平台正式可用。解析调用成本也尚未计入现有套餐预算，正式开放前必须设置费用与使用额度边界。
