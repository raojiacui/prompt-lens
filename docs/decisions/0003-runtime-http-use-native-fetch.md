# ADR 0003：线上 JSON 请求统一使用原生 Fetch

- 状态：已接受
- 日期：2026-10-24

## 背景

Vercel 线上日志持续出现 Node.js `DEP0169` 警告。项目业务代码没有直接调用 `url.parse()`；依赖追踪确认警告来自 Axios 的 Node.js 重定向适配器 `follow-redirects`。此前只迁移了 KIE 分析通道，其他 AI、音频分析和视频剪辑请求仍会加载这条依赖链，因此警告仍可能在任意相关函数中出现。

各调用点还分别处理超时、错误响应和 JSON 解析，错误结构不一致，容易在迁移时丢失 HTTP 状态码或上游返回信息。

## 决策

1. 新增统一的 `postJson` 请求封装，基于 Node.js 原生 `fetch` 和 `AbortSignal.timeout()` 发送 JSON 请求。
2. 非成功响应统一抛出 `JsonHttpError`，保留 HTTP 状态码和上游响应数据，鉴权与限流提示继续按状态码处理。
3. 所有线上业务代码移除 Axios，覆盖图片分析、聊天、剪辑指令、音频分段、FunASR 和自托管 FFmpeg 服务调用。
4. 从生产依赖和锁文件中移除 Axios，从依赖树中消除 `follow-redirects`。
5. 保留各功能已有的显式超时预算。音频分段器原有 `120` 毫秒配置修正为 `120_000` 毫秒，和该模块预期的两分钟上游调用预算一致。
6. 本地开发代理继续通过 Undici 全局调度器配置，生产环境不启用代理。

## 备选方案

### 只屏蔽 Node.js 弃用警告

日志会更安静，但仍保留调用非标准旧 API 的依赖，也会掩盖同类问题，因此未采用。

### 固定或升级 `follow-redirects`

当前版本仍调用 `url.parse()`，固定版本无法从根源消除警告；等待上游升级也无法给出确定的修复时间，因此未采用。

### 只迁移当前触发警告的单个接口

其他 Axios 调用仍可能在不同 Serverless Function 中触发相同警告，无法满足全局清理目标，因此未采用。

## 后果

- 线上业务依赖树不再包含 Axios 和 `follow-redirects`，该来源的 `DEP0169` 警告被移除。
- JSON 请求的超时和错误语义集中维护，调用方仍能识别 401、403、429 等状态。
- 原生 `fetch` 不提供 Axios 的自动响应包装，调用方直接读取已解析的数据对象。
- 自托管接口必须返回合法 JSON；成功响应若不是 JSON，会作为明确错误处理。
- Next.js 或其他框架内部仍可能包含旧 URL 解析实现；若部署后再次出现相同警告，需要根据新堆栈继续定位框架依赖。

## 验证计划

1. 单元测试覆盖 JSON 请求体、超时信号、成功响应、HTTP 错误状态与错误数据、非法 JSON。
2. 自动检查生产依赖中没有 Axios 和 `follow-redirects`，线上运行时文件不得重新导入 Axios。
3. 运行完整 Vitest 测试、TypeScript 类型检查和生产构建。
4. 发布后观察 Vercel 日志至少 24 小时；若仍出现 `DEP0169`，记录调用函数和堆栈以判断是否来自框架内部。
