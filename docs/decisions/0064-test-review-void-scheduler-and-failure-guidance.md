# ADR 0064：作废旧测试复核、恢复正式回调及完善失败提示

- 日期：2026-11-13。
- 状态：旧测试任务已作废并零扣费结清；正式回调已恢复、扫描 200 和空闲挂起已验证。页面提示本地实施中，等待负责人确认发布。
- 关联：ADR 0037、0046、0047、0063。

## 背景与授权

负责人明确要求将唯一旧测试待复核任务人工作废，接着开启正式 Worker 回调，并在失败或中断时提示可更换模型重试及失败不扣积分。负责人另外选择：页面修改先完成本地测试，等待本人确认发布。因此本次允许处理指定测试任务与恢复 Fly 回调，页面改动不推送或发布正式 Web。

## 决策

- 仅处理已核对归属为负责人管理员账号、generation/provider_unknown、无上游任务 ID 或待保存结果的指定旧测试任务。不扩展为自动作废真实用户未知结果，不重试模型，不删除任务和财务记录。
- 复用现有 settleCommercialTaskInTransaction，在同一事务锁定任务、钱包及预留，按 0 积分/0 改写结清，再将任务标为 failed，并追加 manual_test_void 事件和独立 review-release 审计。未知结果正常保留预留的产品规则继续适用；本次为负责人明确确认的旧测试作废。
- 正式 V2 已发布后恢复 COMMERCIAL_RECONCILIATION_BASE_URL=https://prompt-lens.cc.cd，保留正式 prl、独立密钥、当前镜像与规格，验证回调 200、调度进展及空闲挂起。恢复按既有规则处理现存订单及过期内容，用户授权后才执行。
- 页面区分确认失败、状态查询中断、待复核和部分交付。上游模型确认失败可建议换模型重试；网络中断或结果未知继续提示查询同一任务，避免重复提交。平台零扣费仅在后台确认结算为 0 时显示；部分成功按已交付结果结算，自带 Key 的上游费用由供应商账户承担。
- 页面修改只本地测试和提交，不推送 V2；当前正式项目已跟踪 V2，推送会触发正式部署，等待负责人下一次明确发布确认。

## 备选方案与后果

- 只把状态改为 failed：会遗留冻结积分，采用现有原子结算和审计。
- 删除旧任务/财务数据：丢失排障与账目证据，不采用。
- 对所有异常统一承诺不扣费并让用户立即重试：可能误导上游已受理、部分成功或自带 Key 的任务，采用按确认状态和计费来源展示。
- 立即推送文案到正式站：不符合负责人本轮先确认发布的选择，保留本地提交。

## 验证计划

先验证正式回调运行及真实扫描结果，不用页面状态冒充后台交付；再以隔离测试验证上游失败、网络中断、结果未知、部分结算及双语文案，运行针对性回归与构建/类型检查。真实模型、支付及正式页面更新仍按各自授权与验收记录执行。
