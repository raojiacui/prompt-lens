# Architecture Decision Records

This directory records material project decisions so the team can understand why the system works as it does and accurately reconstruct the project history for reviews and interviews.

Create an ADR when a change affects architecture, infrastructure, product behavior, security, cost, or operations. Use a four-digit sequence and a concise kebab-case title, for example `0002-provider-failover-policy.md`.

Each ADR should contain:

- status and date;
- context and constraints;
- the chosen decision;
- alternatives considered;
- consequences and tradeoffs;
- verification and operational follow-up.

Update the existing ADR when the decision evolves. Add a new ADR when a later decision replaces it, and link the two records.
