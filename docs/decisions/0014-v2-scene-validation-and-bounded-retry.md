# 0014：V2 镜头结果校验与一次自动补试

- 日期：2026-10-28
- 状态：实现及本地验证完成；发布状态以对应 Git 提交的 Vercel 部署记录为准。
- 范围：仅 V2 视频逐镜头分析；主站不发布本改动。

## 背景

用户反馈“巨构工业”五镜头中两处未获得提示词，手动重试后成功。只读任务记录显示原失败镜头的供应商结果为 unknown，不能据此认定 KIE 已完整返回空内容。因此同时处理无效完成结果和临时服务异常。

用户明确选择在超时、503/524 等异常后也自动补试一次，并接受首个请求可能已经扣费、补试再次消耗 KIE 额度。这一决定取代 [0012](0012-v2-additive-deepseek-analysis-model.md) 中视频镜头未知结果不自动重提的策略。

## 决策

1. 每个视频镜头校验 generationPrompt、visual、story。空白、零宽字符、空对象、缺失字段、占位提示词、无效场景 JSON 均不作为成功结果。
2. 无效结果、连接或响应中断、超时、408/429 和 5xx 最多自动补试一次，间隔一秒。400/401/403/404/405 等输入或认证错误直接失败。无论两次错误类型怎样组合，都没有第三次自动推理；关闭该路径底层连接补试，避免嵌套重试。
3. 两次使用同一镜头、关键帧、模型和 Key。仅失败镜头重新调用，其他已成功镜头不重复分析。静态图片、改写及概览沿用原策略。
4. 单次请求最多 180 秒，两次连同等待共用 240 秒预算，为 300 秒函数预留保存及结算时间。无模型完成记录的过期恢复仍等六分钟；不会因恢复而重新推理。
5. 未确认的旧请求可能仍在 KIE 执行。补试成功后仍记录 providerAttemptUnconfirmed，保留原场景的供应商占位直到既有六分钟租约到期。现有占位限制按镜头任务计数，无法证明或取消供应商端旧请求；同一镜头在异常期间最多存在两个已发送请求。
6. 自动补试不新建商业任务，不新增用户积分冻结。最终有效成功镜头按原规则只结算一次；失败镜头不计为分析成功。KIE 自身可对两次请求分别收费。
7. 写入已有模型结果前再次检查提示词。保存恢复只重存检查点，不再次调用模型；无效检查点记为失败。界面明确说明未获得提示词，补试耗尽时保留手动重试入口。

## 替代方案与限制

- 仅检验空字符串：无法覆盖原任务记录中的未知请求，不采用。
- 无限补试或重跑整段视频：费用和并发不可控，不采用。
- 切换用户选定模型：会偏离任务快照，不采用。

供应商持续故障时两次仍可能失败；本策略提高恢复机会，不能保证每个镜头成功。此改动不迁移数据库、不更改 Worker、不改写已完成任务或样例。

- TypeScript 检查及 Next.js 生产构建通过。构建使用本地占位配置，仍提示既有 Edge 依赖和 lint 警告。改写回归使用标准 Response 对象和现有 Gemini contents 协议更新旧 mock，运行时代码未新增改写重试。
