# ADR 0031：V2 保留独立分支并在最终发布窗口切换正式部署来源

- 日期：2026-11-08
- 状态：2026-11-13 负责人已完成正式 Vercel 跟踪 V2 及 GitHub 默认分支切换；默认分支已通过 GitHub API 核验。测试项目去留与正式业务验收继续单独处理。
- 关联：ADR 0003、0008、0027。

## 背景

上线准备讨论中曾建议将 V2 合并到 `main`。项目负责人明确希望保留两个分支，并指出测试项目服务于本次上线前测试。双方确认：V2 可以直接作为正式版本来源，正式项目切换应放在准备完成后的最终发布窗口。负责人要求先记录已确认事项，其他事项逐条讨论，实际操作由负责人亲自执行。

## 决策

- `main` 保留旧版本；`prompt-lens-V2` 与其分开，本次上线不合并进 `main`。
- 正式项目 `prompt-lens` 在最终发布时改为跟踪 `prompt-lens-V2`，继续提供 `prompt-lens.cc.cd`；此前维持现状，不在记录方案时修改部署设置。
- GitHub 默认分支调整至 V2 与 Vercel 正式部署分支分别核对，安排在同一最终发布窗口。修改 GitHub 默认分支本身不构成正式部署。
- 测试项目在准备期间继续承担 V2 验收。正式站验收后再决定是否停止测试项目自动构建，当前不删除相关资源。
- 构建保护须按该路线另行准备和验证；实际发布仍遵循本地验证、提交、推送 GitHub、Git 集成部署的顺序，不移除项目隔离边界。
- 2026-11-09 准备进展：已按 [ADR 0042](0042-v2-build-boundary-and-node-parity.md) 准备两个指定项目仅放行 V2/production 的仓库规则；按负责人纠正，后续 V2 统一 Node 24，撤回初次固定 22 的选择。正式项目当前 main 跟踪及正式发布仍未切换。
- 使用 [上线过程记录](../v2-launch-process.md) 逐项记录确认、执行及验证状态。方案确认不自动授权执行上线操作。
- 2026-11-13 执行进展：负责人本人完成正式项目跟踪 V2 及 Web 发布（ADR 0063），随后将 GitHub 默认分支从 main 改为 prompt-lens-V2。助手经 GitHub get_repo 实读 default_branch=prompt-lens-V2；未合并或删除 main，未推送本地待发布修改。默认分支切换后的日志巡检运行来源另行核验。

## 备选方案

- 将 V2 合并到 `main` 后发布：可沿用原生产分支配置，但与负责人本次分支安排不符，不采用。
- 仅修改 GitHub 默认分支：无法完成 Vercel 部署来源与构建规则的同步，不单独采用。
- 上线后长期让正式和测试项目同时跟踪同一分支：本次不预先决定，待正式站验收后安排测试项目用途。

## 后果

旧版分支继续保留，V2 正式发布需要调整正式项目跟踪分支与对应构建保护。默认分支变更对后续提交、PR 和其他集成的影响，需要在最终窗口前检查。分支、配置和 Worker 的回退方案须分别准备，不能只依赖保留旧分支。

## 验证计划

- 执行前确认其他上线前置事项、验收、备份及回退方案均已完成，记录确定的发布 SHA。
- 核对正式项目 ID、Git 来源分支、构建保护、部署 SHA 及正式域名指向，保留测试阶段的隔离限制。
- 正式部署后完成真实业务验收，再决定测试项目自动构建的去留。
- 本轮仅记录决策，不变更 GitHub 设置、Vercel 配置、数据库、Worker 或正式部署。
