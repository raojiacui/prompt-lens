# ADR 0005：为 V2 线上测试账号发放测试积分

- 状态：已接受
- 日期：2026-10-23
- 决策方：Prompt Lens 项目团队

## 背景

V2 线上测试需要验证自动拆镜、平台模型分析、任务预留和积分结算。测试账号 `raojiacui@gmail.com` 在独立 Supabase 项目 `prompt-lens-v2-test` 中尚无商业积分钱包，因此页面只能使用整段分析，无法覆盖付费拆镜流程。

直接修改钱包余额会破坏商业钱包与积分批次之间的对应关系，后续任务预留会因为找不到可分配批次而失败。测试积分也不能伪装成真实付款订单。

## 决策

- 在 Supabase 测试项目 `mwczjgflbmzgvebfilnf` 中为 `raojiacui@gmail.com` 发放 1000 平台测试积分。
- 同一事务中创建商业钱包、可用积分批次和商业账本流水，保持钱包余额与批次余额一致。
- 流水事件键为 `test-grant:v2:2026-10-23:raojiacui:1000`，元数据明确标记来源为 V2 线上测试、无真实付款。
- 本次操作只影响 V2 测试数据库，不修改正式站项目、正式用户余额、套餐价格或支付订单。

## 备选方案

### 只修改商业钱包余额

操作简单，但任务预留会要求从有效积分批次分配额度，钱包和批次不一致将触发账本校验错误，因此不采用。

### 创建一笔虚拟支付订单

能够复用购买结算流程，但会污染支付订单、营收统计和退款记录，因此不采用。

### 每次测试临时绕过积分校验

无法覆盖真实的预留、扣费和释放流程，也会降低测试结果可信度，因此不采用。

## 影响

- 测试账号现在可以选择拆镜分析并执行需要平台积分的 V2 功能。
- 测试任务会正常从这 1000 分中预留和结算，便于观察真实余额变化。
- 该积分没有真实付款或退款含义，不应计入收入分析。
- 若以后需要清理测试积分，应根据该测试流水和对应积分批次核对已用、预留与可用金额后再处理。

## 验证计划

- 查询商业钱包，确认可用积分为 1000、冻结积分为 0、钱包未冻结。
- 查询有效积分批次，确认可用积分合计为 1000。
- 查询商业账本，确认测试发放流水仅有一条且金额为 1000。
- 刷新 V2 测试站，确认账户显示 1000 积分且拆镜分析可选。
- 完成拆镜测试后，核对钱包、批次、预留和结算流水同步变化。
