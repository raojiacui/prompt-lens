# ADR 0023：补齐 V2 受邀账号的视频链接导入权益

- 日期：2026-11-06
- 状态：已采纳；本地验证通过，发布后需页面复测实际链接导入。
- 关联：ADR 0005、0006、0008

## 背景

用户在粘贴抖音分享内容后看到“套餐链接解析次数不足”，并确认 EasyDown 服务商额度充足。测试库核对显示 `raojiacui@gmail.com` 有 931 分析积分、19 次改写、0 个链接导入请求；历史测试发放只覆盖积分与改写，未发放链接导入次数。前端在调用解析接口之前即拦截，服务商余额没有参与这次判断。

## 决策

- 为测试库 `mwczjgflbmzgvebfilnf` 的指定受邀账号补发 12 次导入权益，与当前体验包数量一致。只新增 0 积分/0 改写的服务器账本事件，关联已有 active 测试批次；不创建付款订单或虚构 purchase 事件。
- 事件键固定为 `test-grant:v2:link-imports:c60d77cc-b1d1-4bbe-905b-80bd54ed9c84`。使用钱包与批次锁校验账号、批次及历史测试发放来源，重复执行必须与原元数据匹配，不能重复增加权益。
- 权益读取保留原购买事件的优先级。仅额外识别精确匹配当前批次的 V2 测试发放事件，要求 0 积分/0 改写、`source=v2-invited-testing`、`environment=prompt-lens-v2-test`、`noRealPayment=true`、批次 ID 及测试引用同时一致，并继续验证次数为正整数。
- 测试权益沿用原用户隔离、active 批次、钱包锁、预留、同请求重放和结算规则；成功解析且保存后计次，失败释放。普通账号无合格权益仍拒绝，正式购买次数不变，同批次不叠加测试发放与购买次数。
- 前后端错误明确显示“当前账号的套餐视频链接导入次数”，避免与服务商解析额度混淆。后台测试发放记录只用于独立测试库，不作为收入或真实支付。
- 只推送 `prompt-lens-V2`，由 Git 自动部署到测试项目；正式项目保持原部署。真实解析验证不触发模型分析或视频生成。

## 备选方案

- 取消套餐校验、直接使用 EasyDown 余额：混淆账号权益与服务商成本，破坏正式计费和测试可信度，不采用。
- 增加分析积分或改写次数：不能补齐独立的链接导入权益，不采用。
- 伪造购买事件或付款订单：污染购买、营收和退款语义，不采用。
- 新增测试开关绕过预留：不能验证正常成功计次和失败释放流程，不采用。

## 影响

指定测试账号可以继续测试链接输入，服务商解析调用仍可能计费。12 次权益会随真实成功导入递减；失败不消耗账号次数，不代表服务商一定没有扣解析额度。其他用户、正式数据库、套餐价格及支付流程不变。

## 验证计划与结果

- 隔离数据库及路由/进度回归 158 项通过、1 项既有原生数据库专用测试跳过。覆盖正常预留与结算、失败释放、跨账号隔离、失效批次、错误来源/环境/关联/事件键、非法次数、购买优先级及不创建付款订单。TypeScript 和 Next.js 生产构建通过。
- 数据库独立回读：新事件 0 积分/0 改写、12 次；实际应用函数计算 total=12、used=0、remaining=12。钱包仍为 931 积分、19 次改写、无预留。
- 检查发现本地入库地址和 EasyDown 配置与 V2 线上不同；通过只读 CLI 获取测试项目可读配置，使用 V2 Worker 地址预检鉴权与就绪成功，未更改 Vercel 设置。生产类型的敏感 Worker 密钥不可回读，沿用已有本地凭据，实际预检验证其可用。核验后将两项可读配置同步至唯一的本地 `.env.local`，删除临时配置快照。
- 用户提供原链接 `https://v.douyin.com/qvcLSvq9no8/`。服务器集成验证请求 `40d67b18-f348-4fae-a976-d8bba08038c4` 正常预留，通过 Worker 预检后，在本机连接 EasyDown 时出现 `fetch failed`，没有得到服务商响应。失败按原流程释放，不能确认服务商是否收到请求，不连续重复调用；未保存结果，未调用模型。
- 尚未完成浏览器中的“解析→保存→成功计次”验收，此项保持未通过，不能以权益修复、模拟回归或部署就绪替代。发布后需在真实 V2 页面用原链接复测；核对 Git SHA、固定测试域名和正式站部署 ID。
