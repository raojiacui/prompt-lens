# ADR 0048：先准备可执行的上线观察与故障操作单

- 日期：2026-11-09
- 状态：操作单编写及源码核对完成；人工观察安排待负责人确认，实际业务、邮件和调度验收未执行。
- 关联：ADR 0031、0032、0037、0046、0047；上线记录第 018 项。

## 背景

负责人要求继续上线准备。现有任务详情、Web 日志、Worker 调度状态及业务复核邮件可用于定位问题，但源码没有已验证的独立调度失联告警。需要明确每个入口能证明什么，以及遇到故障时先保存哪些证据，避免重复付费请求或误判登录/页面同步失败为后台失败。

## 决策

- 编写 [上线观察与故障处理操作单](../v2-launch-observation-runbook.md)，包含正式项目识别、任务阶段、Web/Fly 日志事件、建议首小时人工观察、每日 Cron 复查及回退边界。
- 本轮只准备操作单，不新增监控订阅、不配置第三方服务、不设置自动邮件、不周期探测 Worker、不进行线上故障演练。人工观察方案仍是建议，不能记为负责人已经承诺值守。
- 以已有日志和业务复核邮箱作为可用入口；明确自动失联告警的缺口，不以“有 Gmail 配置”证明调度器停止后仍可主动告警。是否增加独立告警另行决定。
- 将连续三轮调度失败作为建议人工排查提示，2 分钟无检查点沿用页面提示；均不自动判失败、扣款、回退或改变任务生命周期。轮次可能包含 290 秒请求等待，不能写成固定三分钟。
- 将回退平台限制加入最终发布核对：官方说明 Hobby 仅可快速回退到紧邻的上一个正式部署；实际套餐、目标保留及可选范围须在发布窗口重查。明确回退 Web、Cron 定义、项目 Cron 开关与外部数据库/Worker 的边界。

## 备选方案

- 立即新增自动告警平台：需要确定渠道、成本、权限、采集范围及交付测试，超出本轮操作单准备，不擅自实施。
- 只保留一句“看日志”：缺少入口、事件和恢复顺序，不能支撑上线排查，不采用。
- 持续请求 Worker 健康地址维持在线：会影响按需挂起和费用，不作为默认观察方式。

## 后果及验证

- 通过源码核对任务页的同步/检查点提示、逐镜头阶段，Worker 的扫描/挂起/唤醒日志、Cron 的 recoveryErrors 和查单流程；未调用这些正式业务接口。
- 查阅 Vercel Runtime Logs、Instant Rollback 及 Fly logs 官方文档，操作单附对应来源；未操作平台回退或改变发布规则。
- 操作单已区分静态准备和真实验收，所有验收模板保持未执行；首小时人工观察及独立告警选择仍待负责人确认，不能将本项完成视为整体上线条件已通过。
- 本轮仅文档变更，执行差异/格式检查并本地提交；无需构建应用或触发测试部署。不改生产数据、线上配置、自动化、Worker、GitHub 分支或正式部署，不发送邮件或请求付费模型。
