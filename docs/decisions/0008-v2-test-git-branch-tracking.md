# ADR 0008：测试项目跟踪 V2 分支并限制为两个测试邮箱

- 状态：已接受；仓库绑定、两个邮箱白名单和部署验证已完成
- 日期：2026-10-24
- 关联：ADR 0002、ADR 0003、ADR 0007

## 背景

测试项目此前通过 CLI 手动部署，未连接 GitHub。项目负责人决定让后续 `prompt-lens-V2` 分支推送自动更新测试站，同时强调只允许指定的两个测试邮箱使用，正式站继续保持独立。

## 决策

- 现有测试项目 `prompt-lens-v2-test`（`prj_wGvOLlXsOzpVUGZiK3spsAIxXAjI`）连接 `raojiacui/prompt-lens` 仓库。
- 测试项目的 Production Branch 设置为 `prompt-lens-V2`，后续该分支推送使用测试项目的 Production 环境变量更新固定测试地址。
- 正式项目 `prompt-lens`（`prj_LA38e0saqqVw1OkQ95AyoMx5vjIV`）继续跟踪 `main`；本轮仅对其设置和部署做只读核对。
- 测试项目配置 Ignored Build Step：Git 提交分支为 `prompt-lens-V2` 时继续构建；来自其他分支的提交跳过构建；没有 Git 分支变量的手动部署仍允许执行。这样可以避免同一仓库的旧版分支在测试项目生成缺少当前应用白名单逻辑的预览。
- Production、Preview、Development 和本地白名单统一为 `raojiacui@gmail.com`、`raojinbo@gmail.com`。移除历史拼写错误地址。
- 保留应用层白名单、普通账号和有权益账号的真实权限校验，其他登录方式维持本轮约定的现状。
- 本轮不推送仓库。远端 V2 分支尚未包含本地最新会话刷新修复，连接仓库和设置分支没有改变当前测试地址的部署；为应用精确的两个邮箱名单，使用当前工作区对测试项目进行一次手动刷新部署。

## 备选方案

- 继续完全手动部署：容易遗漏分支推送后的测试环境更新，不作为后续默认流程。
- 将 V2 分支配置为正式项目的 Production Branch：会让未发布版本影响主站，不采用。
- 允许测试项目构建所有仓库分支：旧版代码可能没有测试访问限制，且预览配置不同，增加无关部署和测试混淆，不采用。

## 影响

- 推送 V2 分支后，测试站会自动构建更新，失败时需检查该项目的构建日志。
- 测试项目内部的 Production 标记对应固定测试地址，不会将 V2 发布到正式域名。
- 当前本地未推送修复继续保留；后续推送需要包含这些提交，避免旧代码覆盖已经修复的线上行为。
- 环境变量继续单独维护，分支推送不会自动同步本地 `.env.local`。
- 所有决定写入本地 ADR；本轮未改变正式分支、正式环境变量、正式域名或正式项目设置。

## 验证计划

- 回读测试项目 Git 连接，确认仓库及分支完全匹配。
- 回读 Ignored Build Step，确认仅构建目标分支的规则生效于配置。
- 回读三个环境中的白名单，确认精确为两个指定邮箱；同步本地名单防止以后重新引入错误地址。
- 执行访问控制与会话刷新相关测试；部署后验证旧拼写邮箱、其他邮箱无法请求验证码，匿名访客无法直接访问工作台。
- 核对固定测试地址部署状态为 Ready，正式站部署 ID 仍为 `dpl_Dh4d9z2Wyu3LLJYU344BxSsjYtc9`。
- 后续首次推送时核对 Git webhook 触发的实际自动构建；本轮只验证绑定设置，不伪造推送验收记录。
