# ADR 0078：Waffo 多币种换算与海外银行卡结账

- 日期：2026-11-19
- 状态：按负责人要求实现；支付关闭，线上配置和真实银行卡交易待验收。

## 背景

负责人展示人民币结账仅有支付宝与微信，并提供客源分布，要求至少支持海外银行卡及币种转换。前一版代码固定 CNY，未覆盖海外付款需求；官方 SDK 的一次性付款币种矩阵区分人民币钱包与外币刷卡。

## 决策

- 保留现有 CNY 套餐基价及所有权益。支持 CNY、USD、JPY、HKD、EUR、GBP；海外使用 card/applepay/googlepay 白名单，人民币由 Waffo 返回其实际可用方式。
- 通过官方 GraphQL rate(CNY,目标币种) 查询换算，不硬编码汇率。缓存最长五分钟且不超过网关有效期，查询失败或过期不创建新的外币订单。
- 汇率按十进制定点整数计算并四舍五入到目标币种最小单位；JPY 为整日元，其余已支持币种两位小数。保存人民币基价、汇率、网关汇率引用、报价时间与有效期。
- 定价页可选择付款币种，展示换算参考价；创建订单时由服务器锁定最终金额，付款窗口展示该订单金额，用户再主动进入 Waffo 结账。重试及重开使用原订单快照，不按最新汇率重算。
- 按国家信息建议中国大陆 CNY、日本 JPY、香港 HKD、欧元地区 EUR、英国 GBP，其余及未知地区 USD；支持手动覆盖。SGD、IDR、CAD、TWD、TRY 未列入已验证的刷卡结账矩阵，先使用 USD，不能只展示本币却声称按该币种扣款。
- 原 amountCents/paidTotalCents/paidTaxCents 字段在 Waffo 路径解释为订单币种的最小单位；接口新增 amountMinor 以明确语义。所有客户及后台订单/退款显示必须携带实际币种；支付宝 CNY 历史路径保持原语义。
- 回调币种与订单完全匹配；退款按原实付总额、原币种执行和核查，不按退款时汇率转换。人民币历史订单保持可处理，无新增数据库迁移。

## 备选方案

- 固定外币营销价格：需要负责人逐个批准，当前以自动换算满足需求。
- 所有地区只收美元：实现简单，但未覆盖中国大陆钱包、日本和香港的本币展示需求。
- 把金额数字原样换币种代码、统一除以 100 或前端决定金额：会产生错收和日元百倍错误，不采用。

## 后果与验证计划

商品后台须启用这些结账币种及支付渠道。需验证官方汇率实际响应、日元整数金额、换汇失败、重试锁价、跨币种伪造回调、同币种到账/退款、定价与账单显示和桌面/手机币种切换。本地模拟不能代替网关银行卡付款；测试库、Webhook、Key 等配置仍待负责人操作，正式收款继续关闭。
