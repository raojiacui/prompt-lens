# ADR 0077：Waffo 一次性套餐支付、到账与退款集成

- 日期：2026-11-19
- 状态：已获负责人授权实现；收款默认关闭，开发及本地验证中。

## 背景

负责人确认 Waffo 商户审核通过，要求补齐支付代码，需要配置环境时由负责人操作。原代码只有受测试项目限制的沙盒结账与验签回执，不保存订单或发放权益；现有商业钱包、人工退款和购买页面绑定支付宝。

## 决策

- 固定官方 @waffo/pancake-ts 0.28.0，使用官方结账、RSA 回调验签及客户退款工单接口，移除旧手写沙盒结账入口。参考：https://github.com/waffo-com/waffo-pancake-sdk-ts 。
- 增加 waffo 订单 provider 和私有去重事件表（0027）；先本地空库测试，等待负责人配置后再迁移独立测试库。此轮不修改线上数据库、环境变量或收款状态。
- 三个现有一次性 CNY 套餐分别映射测试/正式产品。开关 WAFFO_PAYMENTS_ENABLED 默认关闭，test 只允许测试项目，prod 只允许正式项目 Production。商户 Key 与商品必须属于对应环境，不能用审核通过替代支付权限和实际交易验收。
- 本地订单在创建结账前持久化，固定用户、SKU、权益、价格、币种、门店及环境快照，使用同一 requestId 重试；付款返回页仅轮询，不凭跳转发权益。
- 仅验签成功且门店、环境、订单、商品元数据、用户、币种及价格与实付校验一致后，事务去重并发放商业钱包权益。缺少金额证据或返回不匹配时保持未确认，不盲目到账；税额与套餐税前价格分别核对。
- 对退款与异常付款保留人工核查、冻结和审计；复用站内人工退款申请流程，Waffo 退款以网关成功事件或经核实的查询结果为准，不将提交退款工单视为钱已退回。
- 现有支付宝历史订单与退款路径继续工作，不能混用跨 provider 凭据与到账记录。界面仅在服务端配置允许后开放 Waffo 购买，开发期间仍显示待开放。

## 备选方案

- 直接启用旧沙盒接口：没有资金履约逻辑，不采用。
- 付款回跳即加积分：用户可伪造跳转，且会遗漏重复/乱序通知，不采用。
- 测试和正式共用订单状态或只凭邮件匹配：可能跨环境发放或归属错误，不采用。

## 后果与验证计划

本轮交付代码、迁移及配置说明，所有真实支付、真实退款和线上迁移均待配置与独立验收。需测试新下单及重试、原始签名、跨环境/门店、金额/商品不符、重复及乱序通知、事务回滚、退款冻结/恢复、权限与既有支付宝回归。主站开启生产收款须在隔离测试和实际资金链路证据齐全后进行，不能将本地模拟视为真实集成通过。
