# ADR 0083：后台发放有期限的 V2 套餐权益

- 日期：2026-11-23
- 状态：实现与本地验证完成，测试库迁移完成；待 Git 测试发布

## 背景

负责人需要按已注册邮箱向朋友或体验用户赠送现有套餐或自定义权益，并设置 1、7、30 天等有效期。现有后台赠送的是旧版积分，V2 商业账本按购买批次管理且没有到期字段。

## 决策

- 仅管理员可发放，要求目标邮箱已注册，禁止向匿名或封禁账户发放。支持现有三档 V2 套餐和自定义积分、改写次数、链接导入次数。有效期从成功发放时开始，以连续 24 小时计算，范围 1–365 天。
- 赠送使用独立 `admin-grant` 流水及商业批次，记录管理员、备注和到期时间；不伪造支付订单、销售收入或真实付款。请求 UUID 幂等，重试同一请求不重复增加权益。
- 批次新增可空到期时间及过期数量计数。原购买批次不设到期时间，余额与分配使用原事务锁。优先使用最早到期的赠送权益，再使用永久购买权益。
- 钱包读取、任务预留和结算时在钱包锁内回收已到期可用权益；链接导入检查直接排除到期批次，无需依赖定时任务才能阻止到期后消费。到期前已预留的任务允许结算；任务失败或少扣部分若发生在到期后，返还数量记入过期而不恢复可用余额。
- 保持批次守恒：总量 = 可用 + 预留 + 已用 + 过期。回收只影响对应赠送批次；购买权益和已确认支付不变。记录到期回收流水便于核对。
- 不自动邀请、不发送邮件、不更改测试站访问名单或普通权限检查。测试站如需新用户登录仍受既有访问名单约束。

## 备选方案

- 复用旧版积分赠送：无法完整覆盖 V2 的改写和链接导入，不采用。
- 建立虚假已支付订单：会污染财务与退款记录，不采用。
- 只用定时任务回收：定时任务延迟会让到期权益继续消费，不采用。

## 后果

需先应用 0028 迁移再发布代码。钱包读取增加一次事务和到期检查；赠送记录保留在账本，后台按记录展示。未使用的账户可能直到下次访问才落下回收流水，但消费路径按到期时间限制。

## 验证计划

使用隔离 PGlite 测试完整套餐、自定义权益、幂等重试、到期、购买批次隔离、预留跨到期结算、余额守恒与链接导入失效；验证管理员认证、同源请求、参数边界和未注册邮箱拒绝。完成类型检查、相关回归与构建后，按负责人授权先发布 staging/v2 测试环境；正式站不发布。
