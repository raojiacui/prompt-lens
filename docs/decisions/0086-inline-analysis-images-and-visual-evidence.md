# ADR 0086：分析图片内联传递与视觉结果有效性校验

## 背景

2026-11-27 主站 KIE Gemini 3.8 视频分析返回参考图片无法打开、全部画面未知的 JSON，却通过仅检查字段存在的校验，成功结算 6 个站内积分。同日管理员使用 Infistar 分析单张图片约 180 秒超时。三张视频关键帧当前均能下载，不能据此证明上游当时成功读图，也不能断定两个供应商故障原因相同。

## 决策

- 分析客户端在调用供应商前读取已通过业务归属校验的图片，将内容作为内联数据传递。KIE Gemini 按供应商 OpenAPI 使用 `inline_data.mime_type/data`，远程音视频使用 `file_data.mime_type/file_uri`；Infistar/OpenAI 兼容接口使用 base64 data URL。
- 服务端仅从配置的 R2 存储读取图片，使用短期签名 GET，不携带供应商凭据，禁止重定向和任意外网图片抓取。下载最长 15 秒，限制每张 8 MiB、总计 14 MiB，并根据文件头验证 JPEG/PNG/WebP/GIF；内容准备和模型调用共用原请求时间预算。准备失败记录为尚未提交推理。
- 拦截明确声明参考图片无法读取或主要视觉字段全部未知的返回值，保留有效画面中局部未知、没有音频、人物身份不确定等合理情况。复用已有失败状态和结算路径，不将无视觉内容视为有效交付。已有历史账目不自动改写，退款需独立核对。
- 不关闭任何模型、付费能力、登录或后台执行，不切换用户供应商或跨账号使用密钥。

## 备选方案

继续把公开 URL 交给供应商下载无法控制远程读取失败；只加强校验无法恢复读图能力；全局切换模型或供应商会改变用户选择和成本。使用供应商上传接口增加临时文件生命周期和额外依赖，暂不采用。

## 后果

请求体和本机内存增加，受限额保护；过大图片会在推理前明确失败。供应商自身超时仍可能发生，不能承诺内联图片解决所有上游问题。该修复需要真实供应商视觉输出验证，mock 和构建成功仅证明本地链路。

## 验证计划

覆盖两类协议的图片字节、凭据隔离、不可信 URL、下载失败、伪图片、超量流、图片与视频场景的无视觉输出拒绝及局部未知保留。验证既有超时、重试与钱包结算。完成本地检查和提交后按 staging/v2 Git 自动部署验证，核对测试 SHA、域名及正式站部署 ID；正式发布需用户明确授权。

## 真实验证发现与修正

首次 KIE 内联验证仍返回 IMAGE_UNREADABLE。随后逐项核对 KIE 3.8 的 OpenAPI（https://docs.kie.ai/market/gemini/gemini-3-8-flash.md），其图片字段为 snake_case；通用 Gemini SDK 的 camelCase 不能当作该供应商的协议保证。原有远程 fileData 及第一版 inlineData 都不符合该文档。已统一改为文档字段，并以精确请求体测试保护。

用户明确授权后，用同一张 6,657,402 字节 PNG 验证修正后的 KIE 请求，模型正确描述长黑发、黑色扣式外套、木桌和学生大厅，与原图对应，图片协议真实验证通过。此前 IMAGE_UNREADABLE 的返回被测试明确判为失败，没有伪造验收通过。测试只调用模型，不创建业务任务或重提历史任务。32 项协议与图片传递回归通过；修正前完整本地回归为 1288 通过、2 项既有条件跳过，最终发布前继续核对对应代码版本。

同一原图的 Infistar 内联请求也返回黑衣长发人物、背景木桌和书写的学生，两家真实读图均通过。测试耗时 KIE 约 25.5 秒、Infistar 约 31.4 秒。第一次 Infistar 尝试在下载原图阶段超时，尚未发送推理；最终复用缓存的同一原图完成其已授权的一次调用。没有自动切换供应商或重试推理，供应商 key 均未输出或写入仓库。真实验证覆盖接口视觉能力，登录、钱包、后台任务与在线完整流程仍按各自证据判断。
