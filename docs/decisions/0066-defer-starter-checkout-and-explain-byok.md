# ADR 0066：体验包待开放与自带 Key 使用说明

- 日期：2026-11-14
- 状态：本地验证通过，负责人授权推送后正式与测试 Git 部署均 READY。
- 关联：ADR 0039、0058、0065。

## 背景

负责人要求将首页 ¥21.90 体验包也设为“待开放”，并在 FAQ 增加“可以完全免费使用吗？”，说明两次试用后配置自己的 API Key、上传单镜头继续分析的路径。

## 决策

- 关闭体验包的统一 checkoutEnabled 开关，与另外两个套餐保持一致。页面按钮禁用并显示“待开放”，结算 API 和订单创建服务沿用已有 PACKAGE_NOT_OPEN 守卫。
- 保留套餐价格和权益展示。已有订单的查询、付款、通知及权益处理沿用原逻辑。
- 中英文 FAQ 增加免费使用问题：两次试用用完后，可配置自己的 Infistar 或 KIE API Key，上传单镜头进行整段分析；平台不扣分析积分，模型调用费由供应商账户承担，自动拆镜单独消耗平台积分。
- 同步更新原 API Key 问答，移除过期的试用模型名称及当前可购买套餐的引导。
- 首次完成本地验证及提交；负责人随后明确回复“推送吧”，授权将本次变更通过现有 Git 集成发布。

## 备选方案

仅替换按钮文字会留下可直接创建订单的入口，因此复用前后端统一开关。将自带 Key 描述为完全零成本会掩盖供应商收费，因此明确平台积分和模型费用的边界。试用次数、供应商路由和分析计费规则沿用现状。

## 影响

三个套餐均暂停新购。用户仍可使用正常试用权益、自带 Key 和既有套餐权益。本次是负责人明确要求的产品调整，不作为线上支付验收通过的证据。

## 验证计划

验证三个套餐的新订单均被拒绝，未调用支付创建服务；回归既有结算校验与自带 Key 手动上传的零平台积分报价；检查中英文 FAQ、禁用按钮和类型。临时截图和测试输出不纳入提交。

## 本地验证结果

- 三个相关 Vitest 文件共 200 项通过、1 项既有可选外部数据库测试跳过，涵盖三个套餐 API 和服务层拒绝新建订单、自带 Key 手动分析零平台积分、已有订单及钱包结算。
- 浏览器 10 项通过，包含中英文、390/1440 像素、客户端有无会话的 8 组按钮及 FAQ 检查，以及已有订单列表和本地收银台导航回归。20 项需要从首页新购套餐的用例根据套餐开关明确跳过，重新开放套餐后恢复执行；未修改产品配置来迁就测试。
- 浏览器服务使用独立 4112 端口、不可用的隔离数据库地址和专用测试签名会话，保留原邀请名单校验；浏览器 API 均为隔离夹具。没有创建真实支付订单、调用真实模型或写入正式数据。
- TypeScript 检查、修改的产品源码 ESLint 和 git diff --check 通过。测试文件按仓库 ESLint 配置忽略。手机页面截图已人工查看，FAQ 正常展开、三个套餐按钮均为“待开放”。
