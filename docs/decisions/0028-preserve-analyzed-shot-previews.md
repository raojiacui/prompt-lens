# ADR 0028：可靠保存分镜素材并恢复分析后的预览

- 日期：2026-11-07
- 状态：实施中；用户已要求修复缺失预览，发布与数据恢复待验证

## 背景

用户的 V2《圆缺》项目有六条成功分析，只有第五镜头的片段和关键帧仍在分镜及父任务记录中。六个子任务的日志均记录素材准备完成，现有日志不足以断定具体哪个历史写入覆盖了地址。当前代码不检查分镜更新是否命中行，缺少单镜头素材检查点，完成子任务时会整体替换子任务结果；前端对空片段直接隐藏预览。

## 决策

1. 在素材准备事务中同时保存单镜头 `preparedAsset` 检查点、分镜媒体字段及父任务该镜头的数组项。验证分镜 ID、项目 ID、镜头序号及实际命中行数；更新零行必须失败，不能记录素材已保存。
2. 父任务仅原子修改对应镜头数组项，分析进度仅合并其负责的字段。完成子任务保留素材检查点，删除已消费的 `pendingBlueprint`；写入分析结果时同步可恢复的预览字段。失去执行租约时禁止保存素材。
3. 结果页优先使用已保存片段；缺失时使用本镜头关联原视频的精确时间区间预览，无法取得源素材时显示明确状态。区间预览不冒充独立片段，不因此开放下载或发起分析/计费。
4. 仅对用户本次任务补齐缺失素材，校验原视频归属、source hash、区间及存储对象后写回，不重跑 AI、不改提示词和钱包/结算、不重新计算拆镜费用。临时恢复工具不入库。
5. 修复先本地验证、提交、推送 GitHub V2 分支，使用 Git 集成自动部署测试项目；主站保持原部署。

## 备选方案

- 重新分析所有镜头：会重复模型调用和计费，不采用。
- 只在页面补播放器：能缓解显示问题，但不能恢复持久化素材和下载能力，需同时修保存链路。
- 仅把父任务整个 JSON 写回：会扩大不同阶段覆盖其他字段的风险，改为局部合并及镜头独立检查点。

## 影响

现有提示词与分析成功状态保留，素材交付与提示词成功分别验证。已有缺失记录需要单独恢复；单元测试通过不等同历史覆盖原因已完全重现，也不代替线上真实媒体验证。素材检查点使用已有 JSON 字段，不新增数据库结构。

## 验证计划

- 本地真实 PostgreSQL 语义测试：多镜头检查点、父快照丢失后的复用、关联缺失拒绝及执行替换拒绝；模拟 Worker，不调用付费模型。
- 浏览器验证：有片段及无片段两条路径、精确播放边界、失败提示、滚动保留；页面不产生付费请求。
- 恢复前后比较场景数量、提示词摘要、结算及钱包快照；验证六个片段和关键帧可读取，保留恢复报告。
- 发布后核对 Git SHA、Git 来源部署、固定测试域名与主站部署 ID。
