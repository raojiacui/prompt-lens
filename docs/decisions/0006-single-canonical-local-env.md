# ADR 0006：统一使用单一本地环境配置文件

- 状态：已接受
- 日期：2026-10-23
- 决策方：Prompt Lens 项目团队

## 背景

V2 工作目录曾同时存在 `.env`、`.env.local`、部署密钥临时文件、Vercel 同步快照和历史备份。Next.js 会按优先级加载多个环境文件，同一变量分散在不同文件时难以确认最终值，也容易把旧数据库、旧密钥或正式环境地址带入 V2 测试。

## 决策

- 本地运行只使用 `.env.local` 保存真实配置与密钥。
- `.env.example` 作为可提交的无密钥模板保留，用于记录完整变量名称和安全默认值。
- 删除仓库目录中的 `.env`、历史备份、同步快照和一次性部署密钥文件。
- `.env.local` 使用 V2 独立 Supabase 数据库和 V2 独立认证、加密、Cron、Worker 密钥。
- 本地站点与认证地址使用 `localhost`；需要出现在邮件和远程后台调用中的公开地址使用 V2 测试站地址。
- 线上配置以对应 Vercel 项目的环境变量为准，并按 Development、Preview、Production 分环境维护；本地文件不直接覆盖线上配置。
- V2 测试项目与正式项目继续隔离。测试配置不得指向正式数据库或正式 Vercel 项目。

## 备选方案

### 为每个用途保留一份环境文件

文件数量会继续增长，变量优先级和更新时间难以判断，因此不采用。

### 将真实配置提交到 Git

密钥会进入仓库历史并扩大泄露范围，因此不采用。

### 只依赖 Vercel 环境变量

本地开发、数据库迁移和 Worker 联调仍需要本地配置，因此不采用。

## 影响

- 开发者只需维护一份本地真实配置，排查环境差异更直接。
- `.env.local` 仍需通过安全渠道备份，Git 不负责保存其中的密钥。
- 修改线上环境变量后，需要有意识地同步必要变化，避免本地和线上长期漂移。
- `.env.example` 必须随新增或删除的环境变量一起更新，但不得包含真实值。

## 验证计划

- 确认仓库根目录仅保留 `.env.local` 与 `.env.example` 两个环境配置相关文件。
- 确认 `.env.local` 的数据库用户名包含 V2 Supabase 项目标识 `mwczjgflbmzgvebfilnf`。
- 确认本地数据库连接成功，且当前数据库用户属于 V2 项目。
- 确认关键密钥均存在、没有重复变量、没有保留过期 Vercel OIDC 令牌。
- 执行生产构建，确认环境整理没有破坏应用构建。

## 验证结果

2026 年 10 月 23 日完成整理与验证：

- 根目录环境文件只保留 `.env.local` 和 `.env.example`；
- V2 数据库使用 `postgres.mwczjgflbmzgvebfilnf` 租户和 `aws-0-us-east-2.pooler.supabase.com:6543` 事务池；
- 数据库连通性及 V2 分析结构检查通过，迁移状态达到 `0019`；
- `.env.local` 没有重复变量、独立数据库密码变量、重复 Worker 密钥或过期 Vercel OIDC 令牌；
- Next.js 生产构建成功。构建仍报告仓库既有的 ESLint 警告和缺少 GitHub OAuth 本地凭据警告，不影响本次环境配置验证。
