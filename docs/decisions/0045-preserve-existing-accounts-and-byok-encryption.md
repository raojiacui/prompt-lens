# ADR 0045：保留旧账号、会话和 BYOK 加密上下文

- 日期：2026-11-09。
- 状态：只读配置/密文格式核查及 43 项本地测试通过；无需迁移账号或覆盖密钥。正式 V2 发布后的真实旧会话、登录和 BYOK 调用验收仍待执行。
- 关联：ADR 0033、0038、0044；上线过程第 014 项。

## 背景

负责人要求继续上线准备。新老用户的 V2 试用规则已确定，还需确认原账号和已保存 API Key 能延续使用。当前正式 main 使用 BETTER_AUTH_SECRET 派生 AES-256-GCM 密钥；V2 新增可选 BYOK_ENCRYPTION_KEY，若上线时另填不同值，旧密文将无法解密。

## 决策

- 继续使用原正式数据库、用户/账号表和认证 Secret。保留正式未设置 BYOK_ENCRYPTION_KEY 的状态，让 V2 沿用 BETTER_AUTH_SECRET 派生密钥；不从测试项目复制认证或加密凭据。
- 现有密文格式、scrypt 参数和 AES-GCM 算法一致，不进行批量解密、重加密或密钥迁移。需要更换加密 Secret 时必须单独设计迁移与恢复方案，不能作为例行上线配置操作。
- 保留 Better Auth Cookie 名称、数据库会话和已绑定 OAuth 账号；V2 不要求重新注册。旧浏览器会话能否实际延续仍在正式切换后验证，失效时正常重新登录，不以页面匿名健康检查证明会话验收。
- 继续保留不同 provider 的历史密钥数据。当前 V2 设置入口及分析 BYOK 使用 KIE；历史智谱、Gemini、OpenRouter 密钥格式可保留，不转换为 KIE 密钥，也不据此开放未支持的调用路径。
- 本项不写业务数据、重置账号、赠送套餐、读取真实用户密钥内容、联系模型提供方或发邮件。配置无缺口时只记录证据，不为本项重新部署。

- BETTER_AUTH_SECRET 元数据存在，更新时间早于当前旧正式部署；未发现 BYOK_ENCRYPTION_KEY 或正式 ACCESS_ALLOWED_EMAILS 覆盖。未回读认证 Secret 的值，也没有修改变量。
- 严格 TLS 只读事务聚合检查现有 201 条 active API Key，全部匹配原有 iv:authTag:ciphertext 加密格式，没有发现其他格式。查询仅返回 provider、启用状态及计数，不返回密文、明文或用户标识。

## 边界与后续验证

密文格式符合和虚构向量通过能够证明实现兼容，不等同于逐条验证真实用户密文或模型账户授权。正式 V2 切换后，以正常登录流程核对旧账号身份、历史项目可见性、旧会话续期以及所有者授权的 KIE BYOK 最小调用；不读取其他用户明文密钥来扩大验收范围。

下一项仍需核定正式隐藏的 KIE_API_BASE_URL；此前余额查询只验证了官方地址和密钥，不能证明正式运行时隐藏地址。模型真实交付、正式后台调度及支付材料等验收继续保持待完成。

## 替代方案与后果

- 新建账号或迁移用户 ID：会破坏历史记录关联，没有必要。
- 新设随机 BYOK Secret 或整包复制测试变量：会导致旧密文及会话失效，不采用。
- 只看密文格式即宣布真实模型调用已验收：证据不足，保留正式切换后的验证边界。

保留原加密上下文可避免上线时让用户重新保存密钥，同时继续沿用现有认证 Secret 与 BYOK 密钥派生的耦合关系。未来解耦必须另做带数据迁移的决策。
