# ADR 0007：V2 按正式上线行为进行完整线上验收

- 状态：已接受；配置补齐与业务验收待完成
- 日期：2026-10-24
- 决策方：项目负责人
- 关联：ADR 0001、ADR 0002、ADR 0003

## 背景

项目负责人要求线上测试覆盖计划发布的完整产品行为。此前 ADR 0001 仅安排测试人员自带 KIE Key，并未配置平台调用、支付和 OAuth 凭据；ADR 0002 又在邮箱白名单启用时关闭社交登录。这些安排使一部分计划发布的流程无法在测试站验收。

2026-10-24 使用已登录的 Vercel CLI 读取 `prompt-lens-v2-test` 的 Production 环境变量名称，确认现有测试部署尚未满足完整业务验收的配置条件。此次读取未输出密钥值，也未修改线上环境变量或部署。

## 决策

1. 线上测试与计划发布版本保持相同的业务逻辑、登录方式、权限和套餐权益、计费与结算、任务执行及恢复行为。
2. 保持独立的 Vercel 项目、数据库与 Worker，以及受邀邮箱白名单。普通账号与有权益账号都需要验收，不能通过统一赠送权益跳过权限分支。
3. 补齐第三方服务配置和测试域名回调。可以使用独立测试应用或服务商测试凭据，但必须记录与正式服务的差异；支付沙箱通过后仍需要正式支付通道的受控验收。
4. 更正 ADR 0001 中仅依靠自带 Key 覆盖生成测试的安排：平台积分调用和自带 Key 调用都必须测试。凭据缺失时明确记录阻塞项。
5. 更正 ADR 0002 中以白名单为由关闭社交登录的安排：目标行为为已授权邮箱能够使用正式版支持的登录方式，服务端在签发会话时核验授权邮箱。恢复入口前须完成服务端校验、OAuth 配置和回调验证。
6. 禁止以隐藏入口、关闭功能、模拟成功结果、绕过计费或关闭后台恢复来取得验收通过。商业化开关和验收标记只能在其依赖与验证条件满足后更新。
7. 基础设施部署成功、单元测试通过、页面可打开分别记录；只有获得真实业务流程证据后，相应流程才能标记为已通过。尚未实现且暂不发布的产品功能单独说明范围。
8. 测试站变更继续遵循 ADR 0003 的项目隔离与主站部署检查规则。

## 当前配置缺口

以下仅依据测试项目 Production 环境变量名称核对，不能据此断言第三方控制台中的配置或凭据有效性。

| 流程 | 核对结果 | 后续验收要求 |
| --- | --- | --- |
| 邮箱登录与会话刷新 | 邮件和认证变量已存在；此前完成会话刷新修复 | 验证邮件送达、登录、退出及缓存过期后继续使用 |
| Google 登录 | 缺少 `GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`，代码还按白名单关闭入口 | 补齐凭据、测试域名回调与签发会话时的白名单校验，实测允许和拒绝路径 |
| GitHub 登录 | 缺少 `NEXT_PUBLIC_GITHUB_CLIENT_ID`、`GITHUB_CLIENT_SECRET`，代码还按白名单关闭入口 | 补齐凭据、测试域名回调与服务端邮箱校验，实测允许和拒绝路径 |
| 平台积分分析与视频生成 | 缺少 `KIE_API_KEY` / `KIE_AI_API_KEY`；仅存在服务地址、模型及商业化开关变量 | 补齐平台凭据，核验真实生成、结果保存、积分预留与结算、失败处理；另测自带 Key 分支 |
| 支付与退款 | 缺少支付宝凭据及海外支付配置 | 按实际发布的支付通道补齐，验收下单、回调、到账、重复回调、取消、退款和对账 |
| 视频链接导入 | 缺少 `EASYDOWN_API_KEY` | 验证解析、上传、后续分析及失败处理 |
| 背景音乐识别 | 缺少 `AUDD_API_TOKEN` | 若纳入发布范围，补齐配置并实测识别与未识别分支 |
| 欢迎邮件 | 未配置 `WELCOME_EMAIL_ENABLED` | 确认发布范围后按相同标准启用和验证 |
| 商业任务人工复核提醒 | 缺少 `COMMERCIAL_REVIEW_ALERT_EMAIL` | 补齐接收邮箱并验证实际提醒送达 |
| Worker 与恢复扫描 | Worker 地址、密钥与对账变量已存在 | 真实任务中验收唤醒、处理中扫描、中断恢复、完成后挂起及再次唤醒 |

变量存在仅代表有配置记录。本次没有读取线上商业化开关值，因此未将对应功能认定为开启或关闭。

## 备选方案

- 继续仅使用自带 Key 并关闭部分登录方式：减少配置工作，但无法验收平台付费与完整登录流程，不采用。
- 全部开关直接设为开启并填写验收标记：会掩盖真实配置及验证缺口，不采用。
- 使用生产数据库和正式项目完成测试：会影响正式用户及数据，不采用。

## 影响

- 测试需要补齐真实第三方集成，并可能产生经实际操作触发的服务商调用或支付费用。
- 已完成的基础设施工作继续保留；整体状态调整为“基础设施就绪，完整业务验收尚未完成”。
- 本 ADR 更新验收标准；不会自行完成 OAuth 控制台回调配置，也不代表表中业务已验收通过。

## 验证计划

- 逐项确认线上变量、第三方应用与测试域名回调匹配，避免引用正式数据库、Worker 或正式站回调地址。
- 恢复社交登录时，验证已授权邮箱可登录，其他邮箱无法获得测试环境访问权限。
- 逐项执行上表业务流程，记录时间、部署版本、账号类型、任务或订单 ID、预期与实际结果；不记录密钥或验证码。
- 通过真实业务流程验证后再更新对应验收标记；失败和未配置项保持待完成状态。
- 任何测试部署后检查正式域名的部署 ID 未改变。
