# ADR 0089：直接分析结果检查点与不阻塞的状态查询

## 背景

2026-11-28 用户报告 KIE 很快返回但页面等待并中断。测试任务 a0870e3d-825b-49da-b96e-9a8199af0242 的日志：01:44:31.954 UTC 开始模型阶段，01:44:44.647 已返回有效结果；之后数据库仍为 running/cursor=0，未保存场景。当前没有足够分段日志确认连接、事务或运行时中断的具体根因；数据库排查未观察到活动阻塞事务。不得据此宣称全部为 KIE 慢或已确诊某项数据库故障。

## 决策

- 直接分析路径在模型返回后先以执行 ID 条件更新写入 pendingScene 检查点，再进入场景保存事务；事务返回明确提交确认，防止未确认执行被当成成功。检查点不改变钱包或完成状态。
- 恢复优先使用已持久化的模型结果，不读取新供应商 Key、不重发推理；写入场景、更新进度及删除检查点在同一事务内完成，任务行锁及执行 ID 防止重复保存和过期执行覆盖。
- 保存使用 5 秒锁等待及 15 秒语句限制，增加 acquire_connection、configure_transaction、lock_task、save_scene、save_progress、commit 阶段日志和慢保存告警。失败时保留检查点及运行状态，沿用恢复时限，避免立即自循环重试。
- 状态 GET 将收尾恢复放入后台 after，返回当前持久状态，不同步等待保存/结算事务；已有检查点时显示 saving，保持真实状态。数据库未确认的结果不提前交付或结算。

## 备选与后果

仅缩短轮询间隔不能挽救丢失结果；自动重新推理可能重复付费；提前标记完成会使钱包和内容不一致，均不采用。检查点增加一次数据库写入，并临时保存结构化内容，成功落库后移除，沿用既有内容保留策略。模型返回到检查点写入之间仍有极短的进程中断窗口，不能承诺跨外部系统原子提交。

## 验证计划

隔离数据库故障注入保存事务未确认，验证检查点仍在、恢复只调用一次模型、只生成一份场景、过期执行不能覆盖、试用和积分结算正常。验证状态查询不被后台收尾阻塞，运行类型检查和生产构建。只通过 staging/v2 Git 部署，在线完整端到端和实际延迟改善需要新的任务证据；未授权时不发起付费模型测试。
