# 0012：V2 新增 DeepSeek 图片分析模型

- 日期：2026-10-27
- 状态：实现与本地验证完成，等待正在运行的任务结束后发布到 V2 测试站。

## 背景与约束

用户要求 V2 分析模型新增 `deepseek-v4-1-flash`，并明确要求保护正在执行的任务。确认使用 KIE 目录中的 `deepseek-v4-1-flash`，显示名称为 DeepSeek V4.1 Flash。当前 V2 默认模型及已有任务使用 Gemini，主站具有独立发布流程。

## 决策

1. 在分析模型目录新增独立的手动选项，保留 Gemini 默认值、免费体验模型和各自动路由的原选择。
2. 新 DeepSeek 使用 KIE 官方 Responses 协议 `/openai/v1/responses`，将现有文字和关键帧转换为 `input_text`、`input_image`。不向该模型发送视频文件；缺少图片时在发送前拒绝不兼容的输入。
3. 设置 `reasoning.effort=none`，解析最终 assistant 文本，排除推理摘要。只有收到完整 JSON 响应或 `response.completed` 才视为完整输出；截断、超时或未知结果不自动重复提交付费推理。
4. 平台积分和自有 Key 均可显式选择 DeepSeek。平台 DeepSeek 暂沿用现有 Flash 报价规则；购买权限、报价确认、余额冻结、结算与异常退款规则保持原逻辑。后续如调整价格，另行记录决策。
5. 创建报价时保存真实模型 ID，镜头执行与重试读取任务快照。新增选项不会改写已创建的报价或任务，不更改现有 Gemini 请求路径。
6. 仅发布 V2 项目 `prompt-lens-v2-test`。发布前检查分析及生成任务，存在正在执行的工作时暂缓切换域名。不重启 Worker，不修改任务记录或数据库结构。发布后核对主站部署 ID。

## 考虑的替代方案

- 全局把 Gemini 映射成 DeepSeek：会改变默认语义及历史任务执行行为，不采用。
- 只添加前端下拉项：平台报价原先固定选择 Gemini，无法保证实际使用新模型，不采用。
- 自动重试超时或 5xx：供应商可能已完成并计费，会增加重复调用风险，不采用。

## 后果

新任务可主动选择 DeepSeek；旧任务继续使用原模型。DeepSeek 图片理解只基于现有抽帧及文字上下文，无法直接接收视频或音频。供应商仍可能发生服务故障，新增模型不构成稳定性保证。
