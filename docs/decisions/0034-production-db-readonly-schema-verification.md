# ADR 0034：以实际结构核验正式数据库，当前不追加或重跑迁移

- 日期：2026-11-08
- 状态：只读结构核验通过；未执行任何线上迁移、修复或数据写入。
- 关联：ADR 0027、0031；上线过程记录第 004 项。

## 背景

环境变量补齐、正式 SMTP 认证及支付宝只读验签复验完成后，负责人要求继续下一步上线准备。按照先确认依赖再切换正式站的安排，本项只读检查正式数据库是否缺少 V2 所需结构。

正式 Supabase 项目为 `vxlwqiohliynbtjwivte`，测试项目为 `mwczjgflbmzgvebfilnf` / `prompt-lens-v2-test`。本次通过项目列表核实两个项目身份及健康状态，分别查询 PostgreSQL 系统目录，不读取用户、会话、订单或密钥业务记录。

## 决策

1. 先比较正式与测试的实际结构，再独立以仓库 `drizzle/meta/_journal.json` 中全部 25 个迁移（0000–0024）在临时 PGlite 空库中重建预期结构，避免两环境共同漏项。
2. 对每张表比较字段名称、类型、非空属性、默认表达式，以及索引和约束的名称及定义；另核对枚举标签及顺序、RLS 状态、策略数量、索引有效性、约束验证状态和 `anon` / `authenticated` 的有效表级权限。
3. 当前结构与预期全部匹配，不补建表、不重跑迁移、不修改数据，不把测试库内容搬到正式库。
4. 正式与测试的 Supabase 迁移历史记录不同，不能以历史列表长度代替实际结构判断。本次不修补历史账本；后续若启用自动迁移或运行全量迁移，先单独核对并校准 Supabase 与 Drizzle 各自的历史机制，避免重复执行已有 DDL。
5. 本项仅确认结构就绪；不修改商业验收标记，不将结构检查作为正式数据库连接、业务写入、备份恢复或完整支付/分析流程的验收证据。

## 备选方案

- 仅比较正式与测试：可能遗漏两边共同缺失的结构，增加独立迁移重建基线。
- 只检查现有 `db:check-v2` 脚本：该脚本检查至 0019 的部分对象，覆盖不到 0022 会话字段、0023 场景任务、0024 提供商并发槽位，因此本次按完整迁移基线检查，不修改应用脚本。
- 因正式迁移列表较短而重跑全套 SQL：实际对象已经存在，可能触发重复创建或不必要数据变更，本次不执行。
- 直接同步测试数据或覆盖正式库：不属于结构准备，不执行。

## 结果与验证

| 对象 | 迁移重建基线 | 正式库 | 测试库 |
| --- | --- | --- | --- |
| public 业务表 | 38 | 38 | 38 |
| 字段 | 390 | 390 | 390 |
| 索引 | 124 | 124 | 124 |
| 主键、外键、唯一及 CHECK 等约束 | 103 | 103 | 103 |
| 枚举类型 / 标签 | 18 / 102 | 18 / 102 | 18 / 102 |

- 三方字段、索引及约束定义的逐表指纹全部匹配，未发现缺失表、额外表或定义差异；全部枚举标签和顺序一致。
- 非空属性已单独纳入字段比较。PGlite 与托管 PostgreSQL 对非空约束的目录表达不同，约束计数和定义比较排除 `contype='n'`，避免重复统计非空属性。
- 38 张表全部启用 RLS，业务表策略均为 0，`anon` 和 `authenticated` 未获得所查有效表级权限；符合当前仅通过服务端 PostgreSQL 连接访问的方案。
- 两个托管库无无效或未就绪索引，无未验证约束。`session.impersonated_by`、`analysis_scene_jobs`、`analysis_provider_slots` 等近期对象均在完整字段和定义比较内。
- 测试库 Supabase 迁移历史为 25 条；正式库仅记录 0016–0019 及一次安全加固，共 5 条。此差异保留为历史管理待办；不据此推断 0020–0024 的实际效果缺失，也不声称正式历史账本已经校准。
- 本轮所有线上 SQL 均为目录 SELECT；迁移仅在本地临时空库执行，没有线上 DDL、业务写入或数据导出。未部署、修改环境变量、更新 Worker 或切换分支。
- 临时核查脚本及目录结果放在被忽略的 `temp/`，只提交中文决策及上线记录；不额外推送 V2 触发测试部署。

## 后续验证

继续按顺序核对正式存储及 Worker 配套。正式连接可用性、真实任务和支付数据写入、备份保留与可恢复性仍需在对应步骤收集证据。将来任何迁移历史校准或结构修改需单独明确执行范围。
