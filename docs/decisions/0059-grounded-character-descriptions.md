# ADR 0059：人物描述依据画面，降低性别与人物对应误判

- 日期：2026-11-13
- 状态：本地验证通过，待 V2 Git 集成部署核验。

## 背景

用户反馈多个模型在人像场景中反复把人物性别描述错。现有视频及图片分析提示仅包含通用的“描述人物、未知内容不要编造”，未明确发型服装刻板印象、遮挡背影、配音归属及跨字段人物一致性的处理规则。视频目前最多提交三张关键帧，信息不足时不能靠指令保证判断准确。

## 决策

- 视频、整段视频与静态图片分析共用人物描述规则，先观察所有已提供图像，再依据位置、可见外观、衣着和动作区分人物；跨帧保持人物对应关系。
- 只描述画面可见的外观呈现，不据此宣称真实人物的性别身份。禁止仅凭长短发、妆容、服装、职业、行为、声音或题材印象套用男女称呼及代词；禁止为消除不确定性编造身体或性化细节。
- 背影、远景、遮挡或证据冲突时使用“左侧人物／黑衣人物”等稳定中性称呼，并保留具体可见细节；不强制二选一，也不在生成提示词中反复堆叠免责声明。
- 图像优先于项目标题、相邻镜头摘要及语音转录中的人物推断；没有依据时不把画外音绑定给可见人物。保留原始对白文本。
- 在同一次调用中要求模型静默核对故事、人物、动作、说话人归属与最终生成提示词，统一修正无依据的称呼和代词。概览汇总继承镜头人物称呼及其不确定性，不从标题或题材补全身份。
- 成功分析记录 `characterGroundingVersion=1`，便于识别新旧指令结果；历史已保存结果及用户编辑不回写。
- 不新增模型调用、重试、抽帧或外部人物识别服务，不改变模型路由、鉴权及计费流程。

## 备选方案与后果

强制输出男女标签会放大信息不足场景的错误，不采用。全局替换男女词汇无法判断真实画面，还可能篡改对白及用户编辑，不采用。额外调用视觉模型复核会增加费用与延迟，本次不采用。新规则减少指令层面的诱导，仍依赖模型遵从能力和输入清晰度，不能声称已消除误判。

## 验证计划

- 运行已有场景分析、生成提示词、改写和供应商协议回归，检查语言、结构、人物细节传递及既有请求次数约束；完成类型与构建检查。
- 人工检查视频与图片共用新规则，概览不强化不确定人物身份。纯指令调整不新增断言指令字符串的镜像测试。
- 不发送真实付费请求。隔离回归只证明流程兼容性，人物性别描述准确率仍待有明确参考答案的错例对比，不能提前标记质量验收通过。
- 本地验证和提交后推送 V2 分支，核对 Git 部署 SHA、测试域名和正式站部署不变。

## 本地验证结果

- 现有 6 个测试文件、91 项回归全部通过，覆盖场景分析响应、生成提示词、改写、KIE 及无限星河协议。测试均使用模拟响应，未调用真实模型。
- `npm run build` 通过，包含类型检查；`git diff --check` 通过。视频和图片共享规则，概览继承人物描述的调用路径已人工检查。
- 以上结果证明流程兼容性。尚未进行带标注错例的真实模型对比，人物描述质量验收仍未完成。
