# ADR 0019：失去镜头执行权时立即退出

- 日期：2026-11-03
- 状态：隔离回归通过，待 V2 发布
- 关联：ADR 0017、0018

## 背景

排查首镜头故障时，任务 82da8eb6 的后续镜头日志出现多个 `ANALYSIS_EXECUTION_LOST`，随后有有效执行成功保存。这些记录证明执行 ID 校验拒绝了过期调用，不能据此断言存在重复模型调用。首镜头下载失败仍是独立问题。

已有代码将阶段写入失去执行权当作普通素材失败，并继续尝试写入空结果。空结果写入虽被执行 ID 挡住，后续清理却可能按镜头 ID 释放当前有效执行使用的供应商占位，日志也会误报模型失败。

## 决策

- 素材保存及阶段记录统一使用已有 `AnalysisExecutionLost` 类型，调用失去执行权立即返回，不构造空结果、不请求模型、不释放当前执行占位。
- 模型结果检查点若被执行 ID 拒绝，同样直接退出；该旧执行无法证明自己仍持有占位，不能按镜头 ID 释放其他执行使用的占位。
- 对过期执行只记录脱敏 info 事件，正常模型失败仍保留原错误路径。保留领取锁、并发上限、恢复期限、未知结果不重提及积分结算规则。

## 备选方案

- 忽略执行 ID 继续保存：可能覆盖有效结果，不采用。
- 对所有执行失败统一释放占位：破坏并发约束，不采用。
- 改写领取算法或自动重试模型：当前证据不足，超出本次修复范围。

## 影响

过期回调不再产生素材失败的假诊断，也不会释放有效执行占位。未获确认的供应商结果继续采用保守占位期限，不在此次修复中自动补算或重跑历史任务。

## 验证计划

使用隔离数据库分别在素材准备和模型返回时替换执行 ID，验证旧执行退出、无空结果、无额外推理、有效占位保持。再运行钱包与逐镜头执行回归和类型检查，仅发布 V2。

## 验证结果

- 154 项组合测试通过、1 项既有原生 PostgreSQL 专用用例跳过；包含两项新增执行权替换测试。
- 既有并发用例主动让首任务过期并执行恢复，旧调用返回值由“已执行过”改为“未提交结果”（false）。保留并加强结果不能覆盖、模型只调用两次、未知占位不释放的断言，没有修改产品超时或并发限制。
- TypeScript 和差异格式检查通过。PGlite 结果不能替代真实 PostgreSQL 多连接并发验收；本次没有复跑真实用户的模型任务。
