# ADR 0068：视频生成的真实阶段进度

- 日期：2026-11-18
- 状态：本地实现，待测试站发布

## 背景

视频生成页仅展示笼统的处理中进度条，提交失败也会填到 100%，无法识别提示词审核、提交供应商或模型执行的失败位置。负责人要求像视频分析一样展示各步骤状态。

## 决策

沿用现有界面配色与阶段卡片。自带 Key 流程展示准备任务、提示词审核、提交生成任务、模型生成、结果就绪；平台积分流程增加费用与素材核算、等待后台调度。分别展示每条视频的当前阶段、完成状态、当前阶段耗时与总耗时。

生成提交与平台报价接口通过显式 Accept: application/x-ndjson 回传执行到的阶段和最终响应。原 JSON 调用保留 HTTP 状态与响应格式。流式响应的最终事件携带业务 HTTP 状态，由调用方解包处理；身份认证、来源限制、审核、报价确认和扣费顺序保持原样。

仅显示确认过的检查点，不按时间虚构模型完成百分比；旧任务没有的检查点标记为未记录。失败停在当前阶段，后续步骤未执行。查询中断保留快照并自动重试，不能据此认定生成失败。提交响应丢失、或刷新发生在任务编号返回前时，提示先核对原任务，不自动重新提交。已有平台积分确认继续复用原报价 ID。

阶段协议不发送提示词、密钥、请求头或异常堆栈。生成记录原有返回内容和访问权限不扩展。浏览器断开只停止写入进度流，不重试或主动取消供应商调用。

## 替代方案

- 前端计时模拟每一步：无法反映审核失败位置，不采用
- 新增持久化进度任务及独立队列：超出本次界面改进所需范围，不采用
- 仅显示供应商生成阶段：遗漏请求提交前的审核和费用核算，不采用

## 影响与验证

无需数据库迁移或新增依赖。生成页刷新时保留恢复的任务，不再因 URL 中的初始提示词清空进度。完成类型检查、审核与报价回归、流式分块和中断测试，及桌面/手机中英文的失败、状态恢复与完成浏览器用例。真实供应商调用和线上流式交付仍需发布后核验，本地模拟验证不等同真实生成验收。

## 本地验证结果

- 新进度协议、组件、原审核、报价提交、模型路由、供应商 Key 回归：44 项通过
- 隔离积分钱包事务回归：147 项通过，1 项原有跳过
- 浏览器回归：14 项通过，覆盖 1440/390 宽度、中英文、双视频、自带 Key/积分来源、查询中断恢复、刷新恢复、审核失败和确认响应丢失
- TypeScript 完整检查、差异空白检查及 Next.js 生产构建通过
- 构建仍提示现有依赖的 Edge Runtime 兼容警告、旧文件 lint 警告、开发配置缺少 OAuth 凭据以及本机多 lockfile 根目录警告；未通过修改发布配置或禁用功能消除这些提示
- 未推送、未部署，未发起真实生成或支付
