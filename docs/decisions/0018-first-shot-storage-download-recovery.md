# ADR 0018：首镜头素材下载故障的恢复与诊断

- 日期：2026-11-03
- 状态：本地故障注入和结算回归通过，待 V2 发布
- 关联：ADR 0016、0017

## 背景与证据

用户反馈首镜头经常没有提示词。任务 `82da8eb6-d836-4a73-9d15-b8022735f15e` 的首镜头在 09:35:11 UTC 以 `MEDIA_PREPARATION_FAILED` 结束，providerOutcome=not_sent、modelMs=0；错误原因为 Worker 返回 HTTP 500，底层消息为 `Media download failed`。第 2–10 镜头均成功。

Fly 日志对应 09:34:56 Worker 从暂停恢复、09:35:11 下载错误。现有代码未记录存储原始 HTTP 状态，因此只能确认媒体读取失败，不能确认是限流、服务端瞬时故障或权限问题，也不能将冷启动直接认定为根因。七日镜头记录中首镜头 2 成功/2 失败，后续镜头 23 成功/2 失败，样本量不足以推断总体失败率。

## 决策

- 将商业素材下载提取为独立模块，仅对受既有来源主机校验保护的存储 GET 执行最多三次尝试。
- 仅重试已知短暂连接故障以及 HTTP 408/425/429/500/502/503/504。401/403、404/410、永久 DNS 失败、大小超限和取消立即失败。三次尝试共享 60 秒预算，每次从零覆盖临时文件并重建 SHA-256，保留 100 MB 限制与报价 sourceHash 校验。
- 下载重试发生在抽帧、素材上传和模型调用之前，不重提付费推理，不增加 Web 层重试，避免重试层数相乘。
- 下载日志只记录尝试次数、上游 HTTP 状态和安全错误码；不保存签名地址、存储响应正文或原始网络异常。向 Web 传递下载失败、超时、无权限、不存在和超限的独立错误码。
- 镜头结果和后台详情保留具体错误码；页面将已知素材失败解释为素材准备/下载失败，避免笼统显示 Analysis unavailable。历史已保存记录通过错误码改善展示，不改写用户记录。
- 补齐 Docker 构建白名单中的存储来源校验与下载模块。只发布独立 V2 Worker 与 V2 Web，保留原有密钥、邀请名单、并发和积分规则。

## 备选方案

- 自动重跑首镜头模型：本次模型未请求，重跑模型不能解决素材读取问题，也可能扩大费用，不采用。
- 忽略 sourceHash 或改用任意外部地址：破坏素材一致性或来源限制，不采用。
- 对全部错误无限重试：会掩盖权限、文件不存在等永久故障并拖慢任务，不采用。

## 影响

暂时性存储故障可在原素材准备请求内恢复。持续故障仍会明确失败，其他镜头继续按现有规则执行。日志可区分后续故障的上游状态；历史日志缺失的 HTTP 状态无法补回。

## 验证计划

- 注入首个 GET 503、连接重置、部分响应中断，验证恢复后的字节和哈希；覆盖三次上限、共享预算、取消、403/404 不重试和大小限制。
- 验证错误码穿过 Web、镜头结果和诊断投影；失败前不调用模型，未交付素材不扣费。
- 执行相关回归、类型检查、构建。仅在 V2 无活动任务时部署 Worker/Web，使用合成视频验证真实上传、读取、首镜头素材提取，不调用模型。
- 发布前后核对正式站部署 ID，并记录实际结果。用户真实首镜头成功率仍需后续样本核验。

## 本地验证

- TypeScript 与 Worker JavaScript 语法检查通过；故障注入没有调用真实模型。
