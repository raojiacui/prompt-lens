# ADR 0035：按 prl 核验正式存储，保留样例资源并区分桶级与运行时证据

- 日期：2026-11-08
- 状态：桶级配置及签名传输验证通过；正式 V2 Web 与 Worker 的完整存储链路待对应发布验收。
- 关联：ADR 0031、0033、0034；上线过程记录第 005 项。

## 背景

负责人要求继续下一步上线准备，并明确正式站实际使用 `prl` 存储桶。本地 `.env.local` 指向 `promptlensdev`，两者必须分别核查，不能把开发桶测试当作正式桶证据。

Vercel 正式项目的 5 项 R2 配置都存在且为 sensitive，平台不允许回读明文。本次未请求这些值、未降级其类型，也未覆盖配置。通过已有本地 R2 凭据只读确认其具有访问两个桶的权限，然后分别验证明确指定桶的签名传输，不把本地凭据等同于正式部署实际使用的凭据。

## 决策

1. 正式业务存储以负责人确认的 `prl` 为准，保留现有正式 R2 变量；开发桶 `promptlensdev` 保持开发用途。正式 Worker 后续必须核对为 `prl` 及对应公开域名，不能直接复制测试 Worker 的存储配置。
2. 读取 CORS 和生命周期配置，不修改桶设置。实际验证包含带 Origin 的 OPTIONS、预签名 PUT、S3 HEAD、公开 GET 及内容比对；仅在专用诊断前缀创建独立 UUID 的微小文件，并只删除本次创建的对象。
3. 继续保留开发桶内已经公开使用的样例及邮件图片。本次上线不迁移这些资源，不因测试项目停用而清空其存储。
4. 保留 `prl` 现有生命周期规则，避免影响旧站素材及回退。V2 新路径由项目保留期和引用感知的清理机制配套验证，不盲目扩大桶级删除范围。
5. 桶配置、传输、用户反馈、历史业务记录和运行时端到端验收分别记录。正式 V2 发布后仍须在正常登录态下验证 Web 生成的签名、上传完成回执、Worker 下载/输出和任务后续读取，不提前标记通过。

## 验证证据

| 对象 | 正式桶 | 开发桶 |
| --- | --- | --- |
| 桶名 | `prl` | `promptlensdev` |
| 公开域名 | `https://pub-93c2334144db44c1b97cb34effed3a19.r2.dev` | `https://pub-838ceb4cc82146c2b99d5f06b4751da6.r2.dev` |
| 诊断 Origin | `https://prompt-lens.cc.cd` | `https://prompt-lens-v2-test.vercel.app` |
| OPTIONS | 204，allow-origin 匹配 | 204，allow-origin 匹配 |
| 预签名 PUT | 200，allow-origin 匹配 | 200，allow-origin 匹配 |
| S3 HEAD | 68 字节，image/png，大小匹配 | 68 字节，image/png，大小匹配 |
| 公开 GET | 200，跨域响应匹配，字节摘要一致 | 200，跨域响应匹配，字节摘要一致 |
| 清理 | 本次对象删除后 S3 HEAD 为 404 | 本次对象删除后 S3 HEAD 为 404 |

- `prl` CORS 已允许正式与测试域名，方法为 GET、PUT、HEAD，AllowedHeaders 包含 Content-Type，ExposeHeaders 包含 ETag；两个来源的只读上传预检均为 204。不修改现有来源。
- `prl` 生命周期包含 7 天中止未完成分片，以及对 `uploads/image/`、`uploads/video/` 前缀的 7 天过期；开发桶只发现未完成分片中止规则。
- V2 Web 上传路径为 `uploads/<userId>/<image|video>/...`，旧前缀过期规则不能代表新路径已覆盖。源码已有项目 7 天保留期、活动任务保护、清理队列和引用检查；其正式调度与实际执行随 Worker 单独验收。本次没有运行业务清理器，也没有改变生命周期。
- 只读查询正式库的最近上传记录，仅取时间、storage 和 URL origin：最近一条为 2026-11-08 09:01:22 UTC，公开来源对应上表正式域名；测试最近记录为 2026-11-07 14:08:32 UTC，对应开发桶域名。新诊断对象的公开内容比对进一步确认上表域名与明确指定桶的对应关系。没有导出用户 ID、文件名、对象路径或图片内容。
- 负责人本轮反馈正式站“已上传成功”。随后核对当前旧版 `main` 源码：选图阶段只调用 `URL.createObjectURL`，实际上传在提交分析时发生；当时近 20 分钟未查询到新的正式上传记录。因此该反馈不能单独计为本轮运行时上传验收。助手此前“只上传、不提交分析”的操作指引不适用于旧版选图流程，已在对话中澄清。本项不为验收额外发起付费分析。
- 当前 11 个公开样例共有 477 条去除参数与片段后去重的 R2 媒体引用，全部指向开发桶公开域名。各样例抽查 1 条代表媒体，共 11 条 HEAD 均为 200；未声称全部 477 条资产或全部镜头预览已检查。
- 正式与测试项目 R2 变量 ID、类型、目标和更新时间在核查前后一致；正式域名仍指向原部署 `dpl_AhKmkGrgiKoL25A8KfS8jcLGcBAV`。

## 备选方案

- 仅看变量存在或仅测试本地默认桶：无法证明正式桶可用，因此显式指定 `prl` 并完成真实签名上传。
- 回读 sensitive 值或改类型以验证：不采用。当前只确认正式变量存在且未改，正式凭据留在正常运行时流程验证。
- 将测试整套 R2 配置覆盖正式项目：可能改变正式素材归属，不采用。
- 扩大 `uploads/` 的桶级 7 天过期：会绕过任务和引用保护，本次不执行，沿用既有规则并记录 V2 清理验收依赖。
- 上线后清空开发桶：会使正式公开样例及邮件资源失效，不执行；如需迁移公共资产，另行制定复制、引用切换和回退方案。

## 后果与后续验证

- 两个桶各创建并清理一个 68 字节诊断对象，路径限定在 `diagnostics/v2-launch-2026-11-08/<UUID>.png`，创建前 HEAD 确认为不存在；没有覆盖或删除业务素材。
- 未修改桶配置、Vercel 变量、数据库数据、Worker、分支或部署。临时脚本和脱敏结果保存在被忽略的 `temp/`，仅提交本 ADR 和上线记录。
- 正式 R2 桶级准备已验证，可继续核对正式 Worker；V2 正式运行时上传完成回执、Worker 存储配套和到期清理仍为后续明确验收项。
- CORS 检查按 [Cloudflare 官方说明](https://developers.cloudflare.com/r2/buckets/cors/) 带 Origin 执行，签名传输参照 [R2 预签名 URL 文档](https://developers.cloudflare.com/r2/api/s3/presigned-urls/)。
