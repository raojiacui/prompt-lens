# ADR 0030：将《圆缺》两批分析合并为十镜头公开样例

- 日期：2026-11-07
- 状态：已采纳，媒体与快照验证后经 V2 Git 集成发布
- 关联：ADR 0013、0022、0026

## 背景

用户指定下面任务的前六镜头与上面任务的后四镜头来自同一个视频，要求按此顺序合并到样例页。来源项目分别为 `27ef2ccf-ac8a-420a-b854-cc42852964a6`（六镜头）和 `829fa49d-b0ea-489c-9fa6-bfed24b736d1`（四镜头），对应已完成任务为 `df543f3e-52ea-4bf9-a713-8e1dc5e3ad7d` 与 `8ccc5530-aad5-4b60-9bd7-389a7718b9f2`。

## 决策

- 样例标题为“圆缺”，排在样例页首位。采用独立公开项目 ID `5c698174-5a21-48cf-9fe5-93cbe2136280` 及合成版本，只发布用户指定的十条真实原始分析，重新编号为 01–10，不修改提示词正文。
- 导出前验证两任务归属、完成状态、版本一致性，以及源文件 hash 和源时长一致。实际选中区间为 0–24.467 秒，前六镜头止于 15.867 秒、后四镜头从该时刻继续，保持原始时间轴，不补出其余未分析镜头。原完整视频时长约 69.544 秒，参考视频保留真实完整时长。
- 合并样例使用同一个已核实的原视频引用，重建公开项目、版本、分镜及分析版本的关联。原项目和任务保持原样，不合并账号数据、不重复解析、不运行模型、不改变积分或结算。
- 后四镜头原记录缺少独立片段和关键帧，公开快照使用同源视频的 `#t=开始,结束` 分段预览，不伪造关键帧，不把片段缺失改写成源记录已生成。前六镜头沿用已核实的独立媒体。
- 沿用静态白名单快照及公开媒体清理保护；去除用户、执行、任务、密钥指纹、存储键、源哈希及诊断信息。只推送 V2 分支，不改主站。

## 备选方案

- 在账号中合并或覆盖原项目：会改变用户已有结果，采用独立公开快照。
- 将两条结果分别上架：不符合用户要求的十镜头连续展示，不采用。
- 重新分析整段或生成后四镜头：会产生额外执行与费用，当前分段预览即可展示，不采用。

## 后果与验证计划

公开快照固定保留这十条分析与媒体，后续修改需要显式更新；被公开引用的源视频及媒体需继续保留。源视频其余部分未作为新增分析发布。

- 逐一验证媒体对象和公开 HEAD，拒绝临时签名 URL。
- 校验十镜头编号、连续区间、同一公开项目/版本/参考视频、有效提示词、内部字段排除及样例清理保护；运行既有样例、清理和视频概览回归及类型检查。
- 核对远端 V2 SHA、Git 来源部署、固定测试域名、公开列表/详情接口与主站部署未变。

## 本地验证结果

- 十个镜头与十条原始提示词已合入独立公开快照，编号及关系一致，时间区间连续，原账号项目未改写。样例总数为十一个，“圆缺”排在首位。
- 35 个媒体展示引用通过存储 HEAD 和公开 HEAD。一次网络中断后使用有限重试及既有本地代理完成校验；未取消检查或接受失效地址。第 7–10 镜头使用已验证原视频的对应时间片段。
- 样例、媒体清理和视频概览共 25 项回归通过，TypeScript 检查通过；内部字段检查通过。临时导出脚本及其输出未纳入提交。
