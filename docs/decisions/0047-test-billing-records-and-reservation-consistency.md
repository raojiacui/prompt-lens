# ADR 0047：测试订单归属及积分预留一致性核查

- 日期：2026-11-09
- 状态：负责人已确认现存订单及积分记录来自本人测试；只读一致性核查通过，无数据迁移或清账操作。
- 关联：ADR 0044、0046；上线记录第 017 项。

## 背景

负责人明确说明旧版未向用户开放套餐收费，并确认“目前这些积分和订单都是我在测试过程中产生的”。因此，之前盘点的记录应称为现存测试订单、测试额度及任务记录，不能描述为旧版真实用户的历史套餐交易。

来源确认不等同于网关支付结果核验，也不要求删除账目。本项继续检查正式库中的预留、钱包和额度批次是否一致，确认上线准备是否需要额外数据迁移。

## 决策

- 将本轮已盘点的现存订单及积分记录按负责人说明归类为测试遗留；这只覆盖本次记录，不将上线后新增交易一律视为测试。
- 保留订单、预留、批次、分配及账本审计记录；不通过直接删除、清零钱包或强行释放预留完成上线准备。
- 通过只读聚合核对预留和钱包、钱包和 active 额度批次，以及 held 预留和批次分配；不返回用户标识、订单号或外部任务号。
- 现存测试数据的归属不再作为旧版付费用户迁移的未知项。测试预留继续保留各自状态，实际支付、模型交付及正式业务验收仍按发布后证据完成；不提前修改验收标记。
- 负责人已确认的七天清理仅覆盖符合条件的过期创作内容。现存测试订单若随上线后的正常调度进入查单或复核，仍须遵守既有验签、关单和交付核查规则，不因“测试”跳过校验；本项没有调用这些业务入口。

## 备选方案

- 因来源未知一直保留为真实用户交易迁移问题：负责人已确认测试归属，此项未知已消除，不继续扩大核查范围。
- 直接清空测试订单和钱包：会破坏关联及审计，且并非本次核对所需，不采用。
- 直接将所有 held 预留标为失败释放：未核实具体交付，可能与后续结算冲突，不采用。
