## 背景

负责人要求继续上线准备。本项确认正式历史队列、正式 Worker 状态、提醒配置和后台处理入口，不将准备操作扩大为执行历史任务、清理数据、发送邮件或发布 Web。

此前只强调恢复 Fly 回调后开始扫描。代码复查发现，V2 vercel.json 还定义了三个每日 Cron；正式部署后这些入口也可能运行。COMMERCIAL_SCHEDULER_ACCEPTED 是准备状态标记，三个 Cron 路由均未以它作为执行开关。因此，将其保留为 false、或继续移除 Fly 回调地址，不能阻止所有后台业务处理。

## 本轮决定

1. 对正式 Supabase vxlwqiohliynbtjwivte 仅执行带 BEGIN READ ONLY 的聚合查询；不返回订单号、用户 ID、素材路径、提示词或密钥，不调用任何调度业务接口。
2. 仅从 Fly 管理接口读取正式及测试应用配置、机器状态、发布记录和密钥名称；不请求 /healthz 或 /scheduler/wake，不启动机器。
3. 在正式部署授权前，先向负责人说明历史处理范围，重新取得发布窗口快照并完成备份；本轮不批准清理、关单、结算、退款或模型重试。
4. 正式启用计划同时覆盖 Vercel Cron、Web 主动派发和 Fly 调度器。不得把单一验收标记作为总开关，也不删除产品后台功能来让验收通过。

## 故障定位与停止范围

| 现象 | 先核对 | 操作边界 |
| --- | --- | --- |
| 回调 401 / 404 | 两端 Cron 配对、正式域名是否已为目标 V2 路由 | 不重复提交用户分析或复制测试密钥 |
| Worker 连续失败、lastSuccessAt 停止更新 | Fly 日志 commercial.reconciliation.failed、Vercel 对应请求及错误 | 日志阈值和通知渠道待确认；不自动再次发起未知结果的付费请求 |
| 唤醒失败 | Web 日志 commercial.reconciliation.wake_failed、Fly 机器与应用归属 | 检查服务后恢复同一任务，避免新建重复任务 |
| 复核邮件失败 | commercial.review.alert_failed、lastNotificationError、收件箱/垃圾箱 | 保护 SMTP 密钥；本次不发送测试邮件 |
| 需要回退旧 Web | 原部署、Git 跟踪规则，以及 Vercel Cron 和 Fly 回调的全部入口 | 按授权控制后台入口后再回退 Web；不能只撤销 Fly 回调便假定所有任务停止，且不回滚财务数据库来覆盖新交易 |
