# ADR 0009：统一认证 Cookie 配置并验证完整会话恢复链路

- 状态：修复已部署；自动回归及线上无效会话检查通过，用户现有浏览器会话恢复待刷新确认
- 日期：2026-10-24
- 关联：ADR 0002、ADR 0008

## 背景

用户在测试站登录后反复遇到 `ERR_TOO_MANY_REDIRECTS`。固定测试地址仍运行预期的新部署，未发生旧分支覆盖。

根因是 Cookie 名称不一致：认证配置使用了 `advanced.cookies.sessionToken`，而安装的 Better Auth 版本在创建 Cookie 时按 `session_token` 键读取自定义配置。该配置没有生效，认证库实际沿用 `better-auth.session_token`；访问中间件却只识别 `prompt-lens.session_token`。缓存失效后，中间件将仍有有效会话的用户送往登录页，登录页读取数据库会话后再送回工作台，形成循环。

原有测试使用手工构造的 `prompt-lens.session_token`，没有覆盖登录库真实生成的 Cookie。此前“过期后走一次刷新”的实现仍有缺口：刷新查询失败或返回失效会话时，回登录页没有停止自动跳转的标记。

## 决策

- 删除无效的自定义 Cookie 配置，认证库、缓存读取和 Token 存在检查共用 `authCookieOptions`，明确保留 `better-auth` 前缀。保持现有浏览器会话兼容，不要求用户清除 Cookie。
- 中间件识别真实的普通 HTTP 与 HTTPS 安全前缀 Cookie；缓存缺失或过期时，已有 Token 的请求进入 Node.js 会话刷新端点。
- 登录页读取到有效数据库会话，但访问缓存尚不可用时，也先进入刷新端点，避免直接跳回受限页面。
- 所有刷新失败路径都返回带 `sessionRefreshFailed=1` 的登录地址，保留库返回的清理 Cookie 响应，停止服务端和客户端的自动跳转。
- 认证跳转响应设置 `Cache-Control: no-store`；拒绝将登录页、刷新端点或外部地址作为登录完成后的返回目标。
- 保留 10 分钟签名缓存、30 天数据库会话及两个测试邮箱限制，继续使用现有登录流程和业务配置。
- 回归测试使用真实 Better Auth 内存适配器创建会话，读取其实际 Set-Cookie 并模拟浏览器 Cookie Jar；测试夹具不访问线上数据库、不发送邮件、不触发付费服务。

## 备选方案

- 只让用户清除 Cookie：用户以后仍会在缓存过期后复现，不能解决名称不匹配的问题。
- 延长缓存有效期：只能推迟故障发生，仍存在不一致的认证判断。
- 关闭白名单或认证缓存：分别改变访问边界或正常认证性能，且无法替代完整恢复链路验证，因此不采用。

## 影响

- 已登录用户可在缓存过期后恢复访问；浏览器拒收新 Cookie 或数据库暂时不可用时，页面稳定停留在登录界面。
- 真实会话回归能捕获登录库与应用 Cookie 配置之间的兼容问题。
- 不轮换密钥，不修改测试白名单、套餐权益、数据库与 Worker 设置。
- 本轮仅部署独立测试项目；正式项目的分支、配置和部署保持原状。

## 验证计划与结果

- 修改前新增回归测试，真实 Cookie 名称场景在 HTTP、HTTPS 均复现错误登录跳转；失效会话和查询失败场景均缺少停止标记，共 4 项回归失败。
- 修改后 4 个测试文件共 30 项测试通过：覆盖真实 Cookie 登录后缓存过期、成功刷新并返回原页面、直接访问登录页、拒收刷新 Cookie、数据库会话失效、查询异常、禁止自循环返回地址和现有访问控制。
- TypeScript 检查通过，受影响的产品代码 ESLint 检查无错误。
- 部署后检查现有浏览器会话可恢复访问，并核对测试站 Ready、正式域名部署 ID 未改变。
