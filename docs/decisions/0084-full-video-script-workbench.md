# 0084 整片解读中的完整脚本工作台

## 背景

长篇整片解读使用固定高度滚动区，阅读和再创作不便。用户确认在现有卡片中默认折叠完整脚本，展开后直接编辑，底部使用 AI 改写，右侧本轮只提供下载图标，悬停说明“导出完整脚本”。本轮发布至 V2 测试站。

## 决策

- 保留概览，使用页面滚动展开编辑器；原分镜列表继续显示。首次从已有分析确定性整理脚本，不额外调用模型。时间点使用原始镜头起止值，标注已有 AI 分析及推断的不确定性。
- 将独立脚本文档放入 `project_versions.metadata.fullVideoScript`，由项目用户归属和项目版本共同隔离；保留最近 20 次已应用修订、10 个 AI 候选，使用行锁和递增 revision 比较写入。无需数据库迁移；后续若有更长文稿或独立查询需求，再迁移到专用表。
- 脚本编辑不修改 `scene_versions`；AI 改写支持整篇或指定镜头，服务端强制保持镜头 ID、顺序、原始时间点，限定镜头时只合并所选文本。模型生成后经过语义复核，用户主动应用才创建脚本修订。
- 复用供应商客户端与商业预留结算。整篇或选定镜头的一次成功候选消耗 1 次套餐改写；自带 Key 由供应商账户承担费用，平台预留为零。两种付款方式均以 `rewrite:script:<UUID>` 做幂等，网络未知结果不自动重发；失败释放平台预留。候选持久化与收费同事务；过期恢复沿用既有六分钟恢复机制。
- 生成期间每个项目版本只允许一个脚本改写。保存保留本地恢复稿，显示保存失败或冲突；冲突必须由用户选择重新加载远端或基于最新修订保留本地稿。
- 脚本随项目版本的现有七天内容清理删除。编辑不延长保留时间；本地恢复稿同样七天到期，不承诺永久保存。账务预留仅保存请求摘要哈希，不保存脚本文本。
- 只导出当前已保存修订，支持 Markdown、TXT、JSON，服务端验证 revision 和归属，禁止静默导出尚未保存或未应用的候选。右侧只放下载图标，鼠标悬停及键盘聚焦显示解释；不展示尚未接入的长视频操作。

## 备选方案

专用文档表具备独立索引与细粒度历史管理优势，但本轮会增加迁移和线上回滚成本。仅浏览器保存无法跨设备读取。直接调用旧分镜改写接口会写回原分镜，违背独立脚本稿要求，故不采用。

## 后果

现有分析、生成与分镜编辑流程继续使用原有数据。脚本历史有数量上限；先导出再清理仍需用户自行操作。真实模型改写与线上登录需单独收集验收证据，不以构建通过代替功能验收。

## 验证计划

覆盖真实非连续时间点、部分失败、指定镜头范围、跨账号拒绝、Origin 校验、revision 冲突、请求重放、失败释放与过期恢复；浏览器检查桌面及 390px 下折叠、编辑恢复、候选差异、导出与悬停。完成本地验证和提交后推送 `staging/v2`，由 Git 自动部署 `prompt-lens-v2-test`；核对远端 SHA、Git 部署 SHA、测试域名和正式域名部署 ID。
