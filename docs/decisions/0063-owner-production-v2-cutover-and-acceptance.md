# ADR 0063：负责人执行正式 V2 切换，调度启用与业务验收分别确认

- 日期：2026-11-13。
- 状态：正式 V2 Web 已发布并通过基础只读核验；负责人后续授权的旧复核作废、回调扫描及空闲挂起已完成，见 ADR 0064。真实业务交付及支付验收待执行。
- 关联：ADR 0031、0032、0037、0046、0049、0050、0062；上线记录第 023 项。

## 背景

负责人要求暂缓删除历史部署，继续正式上线，并坚持亲自操作正式切换。数据库 0025、正式 Worker v15、候选回归、备份及当前旧版回退归档均已完成。助手只读复核后，负责人将正式 Vercel 项目的 Production 分支从 main 改为 prompt-lens-V2，并在控制台发起部署。

## 决策与执行边界

- 保留独立 main 与 V2，不合并分支。正式项目 prompt-lens / prj_LA38e0saqqVw1OkQ95AyoMx5vjIV 跟踪 prompt-lens-V2，正式网站切换由负责人本人执行；助手没有 CLI 上传、提升或额外创建正式部署。
- 平台实录本次 source=redeploy、target=production，Git 来源为 prompt-lens-V2 / b9bd3dd2fb88309d8cc9685bd11b6c288d59a7c3。它使用已推送并在测试项目构建验证的确定提交，不能把平台 source 改写为 git。
- 首次发布后保留当前旧版 dpl_BKjZ5RUGiHomYsV4kBbVXW8gTK4P 及 GitHub 回退归档，不删除部署、不调整存储保留策略。Hobby 直接回退位置需保留；本轮不为补充文档再推送 V2 触发第二次正式部署。执行记录先本地提交，随后纳入下一次获授权的仓库发布。
- Worker 回调恢复会实际开始查单、复核提醒、过期清理和任务恢复，不能当作只读健康检查。负责人收到明确操作说明后询问用途，此回复不构成启用授权；当前仍保持未设置回调地址，等待确认。
- GitHub 默认分支仍 main；最终是否及何时改为 V2 继续由负责人操作。既有 main 巡检仍可观察同一正式项目；调度延迟修复沿用上线后待办，不以默认分支或文件存在推定巡检按时覆盖。

## 备选方案与后果

- 保存分支后继续对旧 main 部署 Redeploy：会重新部署旧代码，不采用。负责人实际部署的 V2 SHA 已核对正确。
- Web 一上线就未经范围确认恢复调度：会触达现存测试订单和复核提醒，超出只读核验，等待负责人确认。
- 为同步上线记录立即重复正式部署：会改变 Hobby 紧邻回退位置及增加部署存储，采用本地记录，下一次授权发布再同步。
