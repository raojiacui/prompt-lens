# ADR 0040：正式模型服务先验证凭据与余额，保留隐藏配置及交付验收边界

- 日期：2026-11-09
- 状态：只读核查完成；两项隐藏配置的处理方式待负责人明确，实际模型交付未验收。
- 关联：上线记录第 010 项、ADR 0033、0039。

## 背景

负责人要求继续上线前配置。正式与测试 KIE 密钥不同，正式服务地址和默认视频模型在 Vercel 中为 sensitive，平台不返回其值。测试站通过的用户反馈不能直接证明另一把正式密钥在正式运行环境的完整交付能力。

## 决策

- 先核实两个项目身份及 Production 变量元数据，只读取平台允许回读的普通 encrypted 值；不尝试导出、解密或改变 sensitive 类型以取得历史隐藏值。
- 使用普通加密的有效平台密钥，只请求 KIE 官方 GET `/api/v1/chat/credit`，不发送用户素材或推理请求。密钥仅留在进程内存，不打印、不写报告或仓库。
- 保留正式现有密钥。余额查询成功只证明该密钥可向官方余额接口认证，不据此声明模型权限、实际交付、Vercel 运行时地址或积分结算全部通过。
- 已向负责人提出将正式 KIE_API_BASE_URL 和 KIE_VIDEO_MODEL 统一为测试站值的具体方案；负责人询问含义，尚未确认修改，故本轮保留原值。
- 替代方案：读取隐藏值或盲目覆盖后记为一致、直接发起付费请求。前者违反配置可读边界并缺少确认，后者超出本轮只读检查范围，均不采用。

## 核查结果

| 项目 | 正式 | 测试 |
| --- | --- | --- |
| 有效密钥变量 | KIE_API_KEY，encrypted | KIE_API_KEY，encrypted |
| KIE_AI_API_KEY 覆盖项 | 无 | 无 |
| 官方余额 GET | HTTP 200，业务 code=200 | HTTP 200，业务 code=200 |
| 查询余额 | 812.86 个 KIE 积分 | 812.86 个 KIE 积分 |
| KIE_API_BASE_URL | sensitive，未回读 | https://api.kie.ai |
| KIE_VIDEO_MODEL | sensitive，未回读 | wan/2-7-text-to-video |
| KIE_AI_BASE_URL | 无 | 无 |
| 分析计费/改写开关 | 均 true | 均 true |
| COMMERCIAL_MODEL_ACCEPTANCE | 未设置，保持原状 | 未设置，保持原状 |

- 两把密钥不同；相同余额不构成同账户归属证明，不复制测试密钥覆盖正式密钥。
- 检查时刻约为 2026-11-09 14:37（Asia/Shanghai），余额是该时点快照，不是可承载并发或长期成本保证。
- 分析与改写模型由源码/注册表选择，默认 Gemini 3.8 Flash；平台视频生成读取报价快照中的模型。KIE_VIDEO_MODEL 是相关视频入口未另选模型时的回退项，不控制所有分析或改写模型。
- 分析客户端采用 KIE_AI_BASE_URL → KIE_API_BASE_URL → 官方地址的顺序；平台商业视频执行路径使用 KIE_AI_BASE_URL 或官方地址。当前无 KIE_AI_BASE_URL，因此本轮余额检查仍不能替代分析客户端隐藏地址的运行时验证。
- Vercel 连接器本轮不可用，改用已登录 CLI 的只读 API 核查，敏感变量保持不读取；临时脚本与脱敏报告保存在忽略的 temp/。

## 后果及验证计划

- 正式密钥与余额没有发现当前阻塞；地址和默认视频模型的值仍未证明一致。由负责人明确是否按测试站已验收值统一，修改时保留密钥和其他变量，并核对项目及正式域名。
- 本地 4 个既有测试文件、46 项通过，覆盖连接/流式超时、密钥来源边界、DeepSeek 协议和改写付款来源。依赖为 mock，不证明线上模型权限或真实计费。首次沙箱因 esbuild 子进程 EPERM 未启动，获准运行后通过。
- 未发起付费推理、创建任务、写数据库、改配置或部署。正式域名仍指向 dpl_AhKmkGrgiKoL25A8KfS8jcLGcBAV。
- 正式模型实际交付与权限须通过明确范围的真实请求、结果保存及结算证据验收，不能提前填写 COMMERCIAL_MODEL_ACCEPTANCE。正式 Web 发布前仍须处理配置不确定项并安排实际验收时间。
