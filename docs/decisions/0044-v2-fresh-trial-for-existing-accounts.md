# ADR 0044：V2 为新老账号统一提供两次独立试用

- 日期：2026-11-09。
- 状态：负责人已确认产品规则；代码、本地 27 项测试和生产构建通过，Git 测试部署 READY 且来源已核验。正式 V2 尚未发布。
- 关联：上线过程第 013 项、ADR 0043。

## 背景

负责人确认旧版用户只有两次试用，没有购买积分套餐；V2 上线时新老用户都按首次接触 V2 处理，各获得两次试用。旧版使用次数不应抵扣 V2 额度。不能通过清空历史日志、修改账号或删除订单实现此规则。

## 决策

- 普通合格账号的 V2 试用默认两次，按账号一次性提供；注册时间和旧版试用记录不影响额度。退出登录、刷新页面、再次部署或回退后重新进入 V2 均不会重复发放。
- 使用现有 V2 专用 trial_analysis_usage 和 trial_analysis_reservations 表计次。没有 V2 usage 行时按 used=0 返回，首次预留时创建计数行；删除从 operation_logs 导入旧次数的兼容分支。
- 旧 main 通过历史日志计算试用，没有使用 V2 计次表，因此无需新表、迁移或批量重置。上线前再只读核验正式 V2 计数未被提前消费；如出现非零记录，先确认来源和范围，不能据此全库清理。
- 保留原有事务行锁、请求幂等、任务失败退次数和超时恢复机制。保留邮箱验证、封禁校验、受邀测试白名单及管理角色规则。
- 本项只改变新旧版试用计数的隔离；试用模型、媒体能力、付费拆镜、BYOK 优先级和套餐权益均沿用现有规则。试用不折算为现金积分，不批量赠送付费套餐。
- 测试库保留已消费的 V2 次数，用于验证计次；测试库与正式库隔离，测试消耗不会扣正式用户的上线额度。

## 替代方案

- 将旧日志次数导入 V2：违背负责人要求，删除该分支。
- 清空全部用户历史或试用表：破坏审计且可能让已使用 V2 的用户反复领取，当前正式数据也不需要此操作。
- 新建第三套计次表或增加发布版本字段：当前已有独立 V2 表且正式计数为零，增加迁移成本而没有必要；未来再次赠送版本试用时单独决策。

## 后果与上线检查

老用户通过原有账号登录 V2 即可使用新额度，不需要重新注册。每个账号最多新增两次平台模型试用成本，使用成功计次及原有预留机制控制并发。本项不代表完整商业上线验收通过。

最终切换前重新检查 V2 计数基线、两次上限和备份；正式发布后以普通老账号验证剩余次数展示和使用流程。正式部署尚未授权，本轮只发布 V2 测试项目。
