# 0015：V2 拆镜结果与报价有效期分离

- 日期：2026-10-29
- 状态：已实现并通过本地测试；发布状态以对应 Git 提交的 Vercel 部署记录为准。
- 范围：V2 测试站的分析前拆镜预览和报价；不修改主站、Worker 算法或正在执行的分析。

## 背景

同一视频的拆镜预览原先在创建 15 分钟后失效，报价有效期为 10 分钟。报价刷新不会延长原预览；后端以 QUOTE_EXPIRED 同时表示两种过期，前端收到后清空拆镜结果，用户重新读取会再次下载视频并运行检测。

用户要求在分析前保留拆镜结果，过期只刷新报价，避免重复占用 Worker 资源。

## 决策

1. 完整的服务端拆镜快照随素材保留，最长为预览创建后的 7 天。报价继续只保留 10 分钟，刷新时按当前定价、所选镜头、模型及 Key 重新生成报价，不触发 Worker 或模型调用。
2. prepare 在用户、项目、完整媒体地址和自动拆镜模式均相同时，先复用已经保存的预览 ID 与切点。名称变化不触发重新检测，媒体地址或拆镜模式变化则建立新预览。复用不占新的检测额度。
3. 在用户级数据库锁内检查缓存及运行中的相同请求；同一素材正在读取时返回 PREVIEW_PREPARING，避免双击、面板重开或客户端响应中断导致重复 Worker 调用。未完成的预处理仍保留原 15 分钟超时恢复。
4. 兼容旧版已经超时的完整快照，包括被恢复任务标记为 PREVIEW_EXPIRED 的行。只复用服务端仍保留的完整结果，不能复用其他原因的失败、已清理内容、过 7 天记录或其他用户的结果。
5. 预览保留与分析前项目状态、所有权及素材清理标记共同检查。开始分析仍验证 sourceHash，使用原服务端切点裁剪，不接受客户端任意边界。既有片段下载按准备 ID 缓存，复用该 ID 同时保留已生成片段的缓存命中。
6. 前端的报价失败和报价过期均保留镜头列表及当前勾选。真正超出素材保留期单独提示 PREVIEW_EXPIRED，要求重新上传，不自动运行拆镜。更换素材、重新加载整个页面后的勾选恢复不在本次实现范围；同一预览面板内的勾选持续保留。

## 替代方案与边界

- 只延长原 15 分钟时限：仍会把报价和检测生命周期耦合，不解决重开面板时的重复调用。
- 只使用浏览器缓存：跨实例和重新打开面板不能稳定复用，服务器也无法保证切点可信。
- 无期限保存：偏离现有 7 天素材保留策略，不采用。重复报价不会延长快照保留期。

报价不冻结或扣除分析积分；仍只有用户确认有效报价后才建立商业执行和余额预留。此改动不更改价格、模型自动补试、检测阈值或源文件变更校验，不迁移数据库，不手动改写用户任务。

## 验证

- 隔离 PGlite 商业流程回归：115 项通过、1 项需要独立原生 PostgreSQL 的既有用例跳过。包含旧 quoted/failed 预览复用、原报价过期后只重新报价、连续 12 次复用只调用一次 Worker、跨素材/项目/模式隔离、并发读取去重、保留期及所有权边界；报价阶段余额不变且不调用 KIE。
- 本地无头浏览器回归：模拟等待超过 19 分钟、自动刷新报价、确认时原报价过期及报价接口失败；拆镜列表和勾选不变，所有报价复用同一个准备 ID，prepare 始终只发送一次。
- TypeScript 检查和 Next.js 生产构建通过。构建采用占位配置，存在既有 lint/OAuth 配置警告。本地浏览器接口为模拟响应，没有调用真实付费服务或修改线上任务。
