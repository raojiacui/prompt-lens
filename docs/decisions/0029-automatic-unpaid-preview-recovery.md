# ADR 0029：导入后自动恢复未付费的分镜读取

- 日期：2026-11-07
- 状态：已实施，本地验证后通过 V2 Git 集成发布；线上原用户流程仍需复测
- 关联：ADR 0024

## 背景与证据

用户再次导入视频后，必须点击“重新读取视频”才显示镜头，明确要求消除这一步。V2 日志于 UTC 13:53:38 记录项目 `24e21b7a-cfd2-4968-8d7a-d83f159cf079` 的 `prepare` 请求发生 `PREVIEW_PREPARATION_INTERRUPTED`；手动重读后，预览 `aed4c2e4-2120-4d04-b632-6852c47eb9ec` 在 UTC 13:54:43 创建并保存 29 个镜头，保留期正常，源素材未过期。

与上一部署的 Git 对比显示，刚才的素材持久化和结果页预览修复没有修改读取准备接口或报价面板。此次暴露了 ADR 0024 仅提供手动恢复的体验缺口。现有记录能确认首次预览写回时执行条件失效，尚不足以断定执行权为何失效；不得把未知原因归结为网络、登录或上一修复。

## 决策

1. 首次读取的预览失效、中断及可重试请求错误，使用同一项目、同一已导入媒体自动重读，最多两次，间隔 1 秒和 2 秒。显示读取状态，连续失败后才保留手动重读入口。
2. 同一素材仍由后台准备时，最多以 2 秒间隔查询十次，由后台复用已有任务。面板关闭或刷新周期更换时清理计时器，不无限循环，不绕过后台限流。
3. 报价阶段预览不可用时，共享上述自动恢复预算，重读后按原起止时间恢复所选镜头，不依据可能变化的镜头 ID 恢复选择。普通报价失败继续保留镜头与选择。
4. 自动路径只调用现有未付费的 `prepare`/`quote`，不调用链接解析、不重新上传、不确认商业任务、不启动模型推理；付费分析继续等待用户明确确认。登录、所有权、权益、项目状态与保留期检查保持原样。
5. 对预览写回零行的异常链补充准备任务 ID，便于将下一次中断与实际记录关联；不记录媒体地址、签名、凭据或令牌。不改写已失效任务强行取得执行权。
6. 保留用户手动重试时重新获得有限自动恢复预算的能力。仅推送 V2 分支，经 Git 集成自动部署测试项目，主站不变。

## 备选方案

- 继续要求每次手动点重读：增加不必要步骤，用户已明确拒绝，不采用。
- 无限重试或自动确认分析：可能放大 Worker 负载或产生额外费用，不采用。
- 为避免错误删除执行权/保留期校验：可能覆盖其他执行或访问不属于当前账号的素材，不采用。

## 后果与验证

短暂中断可自行恢复；持续错误仍会明确显示并停止。自动重读可能产生有限 Worker 预处理，但不重新消耗链接导入次数，也不调用模型。

- 六项浏览器回归通过：普通报价错误保留选择；准备/报价阶段预览中断自动恢复并保留时间区间选择；两次自动重试后停止；付费任务轮询的有效与失效会话刷新。测试拒绝任何链接解析或未授权付费确认请求。
- 类型检查与生产构建通过；完整商业任务回归 137 项通过、1 项既有测试跳过。发布后核对远端 SHA、Git 来源部署、测试域名和主站部署 ID。
- 该测试不代表首次执行条件失效的历史根因已经复现；真实用户原页面复测单独记录。
