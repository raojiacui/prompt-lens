# ADR 0032：只归档旧正式版本并保留原部署作为回退基线

- 日期：2026-11-08
- 状态：已实施，源码归档及线上无变更核验通过；实际回退未执行。
- 关联：ADR 0031、上线过程记录第 002 项。

## 背景

负责人确认旧正式站未使用 Worker，认可给当前旧正式版本打包发布 GitHub Release，并在需要回退时优先恢复 Vercel 保留的旧部署。随后明确授权助手执行本项准备，要求不影响当前线上站。当前正式域名实际服务提交为 `75eb611f8759745ec743818bce24350691d6ab8d`，与远端 `main` 一致。

## 决策

- 标签 `pre-v2-live-2026-11-08` 固定指向核实的旧正式提交，创建独立 Release；不移动标签、不覆盖分支、不合并 V2、不切换默认或正式跟踪分支。
- 使用 `git archive` 直接从该提交生成源码 ZIP，核对归档提交 ID、完整性、全部跟踪文件及哈希。提供对应清单和 SHA-256 附件，不把本地工作区、运行时凭据或临时文件混入归档。
- 记录旧 Vercel 部署 ID 与 Git SHA 的对应关系；实际回退另行确认。此次不调用 Vercel 部署、提升或回滚接口，不改项目配置。
- 本项按旧站不依赖 Worker 的确认，不操作 Worker；数据库、存储及环境变量保持现状。源码归档不替代外部资源或数据库备份，也不代表 V2 与旧配置的兼容验收通过。
- 先核对仓库自动化，再仅推送一个标签。使用官方 GitHub CLI 创建草稿、上传并核对附件后发布，不标记为新正式功能版本的 Latest。
- 上线过程记录与本 ADR 仅本地提交；不为文档额外推送 V2 分支并触发测试部署。

## 备选方案

- 只保留 `main`：分支后续可能移动，增加固定标签和独立下载归档。
- 仅保存源码包：无法保留已构建应用的直接恢复路径，因此同时记录原正式部署。
- 重建或重新部署旧站来“备份”：会产生不必要线上变更，本次不采用。
- 把环境变量、数据库或运行时文件加入公开附件：扩大敏感数据暴露范围，不采用。

- [Release 已发布](https://github.com/raojiacui/prompt-lens/releases/tag/pre-v2-live-2026-11-08)，包含 181 文件的源码 ZIP、基线清单及校验文件；三个附件的服务端哈希均与本地一致，标签与 Release 目标均匹配旧正式 SHA。
- 发布后正式域名仍指向原 READY 部署 `dpl_AhKmkGrgiKoL25A8KfS8jcLGcBAV`；正式项目无本次新增构建，两个远端分支及 GitHub 默认分支未改变。
- 临时产物不入功能提交，未改动原有无关工作区修改。完整基线和执行证据见 [上线过程记录第 002 项](../v2-launch-process.md)。
- 后续正式切换前仍需检查平台部署保留及可回退范围、旧配置/数据库兼容性；本项没有执行回退演练，也未授权后续实际回退。
