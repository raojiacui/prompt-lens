# ADR 0021：改写总时限、失败诊断和遗留额度恢复

- 日期：2026-11-03
- 状态：本地验证完成，待 V2 Git 自动发布
- 关联：ADR 0005、0008、0017

## 背景与证据

受邀账号补充 20 次改写后反馈失败。测试库记录显示：第一轮改写在 14:22:06 UTC 预留，约 54 秒后以 0 次结算；请求返回 HTTP 502，没有新版本，次数已退回。原代码在模型层捕获后重新抛出通用错误，路由也未记录原因，因此无法追溯这轮的供应商错误或语义校验细节。

第二轮于 14:25:51 UTC 预留，超过六分钟后仍 held=1，且没有对应新版本。V2 项目只读配置显示函数默认上限 300 秒。旧代码每轮模型最多 180 秒，最多串行生成、审核、修正、再审核四次，没有全流程预算；函数终止后缺少改写预留的恢复入口。此证据表明存在遗留预留，不能把 CDN 记录的 HTTP 200 当作已完成证据，也不能推断第一轮的确切失败原因。

## 决策

- 显式声明改写路由 maxDuration=300；模型生成和审核共享 240 秒总预算，给保存及结算预留余量。每轮调用使用剩余时间，耗尽后不再发出后续请求。
- 保留原语义审核和最多一次修正，保留原模型及费用来源，不通过取消审核或改用本地文本替换提高成功率。未确认的模型调用不自动重复提交。
- 使用类型化错误保留生成/审核/修正阶段、超时/审核不通过/无效结果/供应商失败原因及异常链。路由返回安全错误码、阶段和 requestId；服务端记录脱敏诊断，不记录完整提示词或 Key。
- 确认失败时在同一事务内退回预留次数并写入失败代码。客户端失败后也刷新额度显示，保留现有同请求 ID 查询与防重机制。
- 为 held 超过六分钟的 rewrite 预留增加恢复。按钱包→预留顺序加锁，设置事务锁与语句时限；已经保存的版本按一次成功结算，没有保存结果的释放次数。恢复只读既有结果，不调用模型。
- 余额查询及同一请求重查触发账户范围内恢复。服务端诊断字段不参与报价重放匹配；原指令、模型、项目和版本等快照仍必须一致。
- 已释放任务的迟到结果不能重新扣次数；保存与结算原子事务会因结算重放不匹配而回滚新版本。已有原版本始终保留。
- 只处理 V2 账号和 V2 分支。按本地验证→聚焦提交→推送 GitHub V2→自动部署执行，不使用 CLI 上传或手动提升。

## 备选方案

- 再增加测试额度覆盖预留：不能解决遗留状态，也掩盖账本问题，不采用。
- 延长每轮超时或降低审核要求：总耗时仍可能超过平台上限，或交付不符合指令的结果，不采用。
- 重跑用户的改写：供应商可能已计费，不能用于恢复原请求，保留用户主动提交。
- 引入新队列表和独立改写 Worker：可用于更长任务，当前先修复既有同步流程的预算和恢复，暂不新增基础设施。

## 验证计划

- 模拟跨轮预算耗尽，确认不会启动额外修正；模拟审核失败与供应商异常，验证安全错误码和原异常链。
- 隔离数据库验证六分钟前不恢复、跨账号隔离、重复恢复只执行一次、保存结果不退款、无结果退回、迟到保存和扣费回滚。
- 验证失败额度显示刷新、类型检查、生产构建及相关回归。模拟模型不等于真实改写成功验收。
- 只针对已确认过期且无结果的 V2 预留运行恢复，再独立核对钱包、批次与结算流水。
- 推送前核对测试项目绑定与活动任务；发布后核对 Git 分支/提交与正式站部署不变。真实改写失败细节需新版本日志或后续用户样本确认。

## 影响与限制

改写继续使用同步请求；总预算耗尽会明确失败并释放次数，长耗时的模型仍可能无法在预算内完成。恢复在余额查询或原请求重查时触发，不保证无人访问时立即执行。新增诊断能定位后续失败阶段，无法补回历史请求已经丢失的供应商原因。语义审核、原模型、账户权限和正常计费规则继续生效。
