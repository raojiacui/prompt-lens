# ADR 0082：结账链接失效后的恢复与明确入口

- 日期：2026-11-20
- 状态：已发布测试站，本地回归通过；真实恢复流程待浏览器复核，生产收款仍未验收。

## 背景

负责人在待付款订单中继续付款仍遇到 Waffo 过期页。测试库中 SDK 返回的结账截止时间仍在次日。直接观察 Waffo 页面请求发现 bootstrap 的 checkoutSession=null，页面将缺失会话统一显示为“链接已过期”；该页面不足以证明实际超过 24 小时，也不能归因于五分钟身份凭证。原实现重复使用业务订单号作为创建会话的幂等键，因此恢复会拿回同一个已失效会话。

## 决策

- 区分业务订单和结账会话：业务订单继续保留同一 ID、外部编号、币种和锁定金额；每次用户打开继续付款或主动重新获取链接，使用新的会话请求 UUID。一次请求的网络重试保留该 UUID，避免超时重试产生重复会话。
- 重新打开既有订单前查询原付款证据；付款已确认时不创建会话。多个会话不代表多份权益，仍按同一业务订单唯一发放。旧标签页必须关闭；已扣款或状态核查中不能引导再次付款。
- 返回 SDK 实际 tokenExpiresAt、session expiresAt 和业务订单 24 小时截止时间三者的最早值为本次链接截止时间。界面到期后隐藏旧链接并提供“重新获取付款链接”。订单超期保留真实 pending 状态，提供明确的套餐页重下单入口，不自行推断支付失败。
- 套餐页显式重新下单必须更新本地保存的请求编号，普通刷新继续复用原业务订单；不能仅跳转套餐页却仍从 localStorage 取回旧编号。
- 页面明确显示付款截止时间、余额与订单页、套餐页；不再只写“返回来源页面”。只通过 Git 部署测试站，待实际恢复与支付到账验证后继续生产发布。

## 备选方案

- 只刷新登录凭证：依然复用失效会话，不能恢复。
- 所有网络重试随机生成业务订单：会重复下单并丢失原锁价，不采用。
- 自动判定旧订单失败或删除：缺少资金证据，不采用。

## 后果与验证

会话可以重新生成，但没有推断旧页已取消。验证同一业务订单的新会话键、同次重试稳定键、锁价和唯一发放、超期订单无链接、过期凭证不返回；浏览器验证时间展示、按钮和真正生成新请求编号的套餐页入口。实际 Waffo 新会话可用性及成功到账仍需线上证据。
