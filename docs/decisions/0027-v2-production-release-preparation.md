# ADR 0027：本轮仅核查 V2 与正式站差异并准备上线清单

- 日期：2026-11-07
- 状态：已接受；正式上线及配置变更尚未授权
- 关联：ADR 0003、ADR 0007、ADR 0008

## 背景

用户报告 V2 各功能测试通过，要求确认主站与测试环境差异并准备上线，随后明确本轮只需要差异核查和准备。核查发现正式服务配置、支付宝验签、Worker 版本、存储归属与 OAuth 验收均有差异。

## 决策

1. 本轮只交付脱敏差异、证据、阻塞项、拟处理步骤和回退要求。保留现有产品代码、构建规则和测试配置，不修改正式环境，不合并或推送 `main`，不发布主站。
2. 未来构建规则调整、正式配置补齐、Worker 更新及正式上线均作为后续执行工作。本轮记录具体方案，不将核查需求自动扩展为执行授权。
3. 正式数据库、用户、钱包、订单、会话密钥和已有 BYOK 解密方式保留。禁止覆盖测试库、搬运测试赠送权益、盲目执行 `db:push` 或重跑历史迁移。
4. 不保存密钥、密文、连接密码或会话。敏感变量不可回读时记为未验证，不尝试绕过平台限制。用户反馈的测试站通过与正式环境验收证据分别记录，不预填验收标记。
5. 后续获准执行发布时，遵循本地验证、提交、推送 GitHub、Git 集成部署的顺序；每次核对项目、分支、SHA 和域名，保留旧应用与 Worker 镜像及商业数据。

## 范围纠正记录

本轮曾将上线准备扩展为构建保护与相关测试修改，并提交、推送 `a1a005f` 到 V2。该自动构建因内联命令超过平台 256 字符限制失败，未接管固定域名。用户澄清范围后，撤回本轮额外代码、构建规则和测试配置，只保留核查文档，以后续正常提交保留更正历史，不重写远端历史。独立 shell 脚本方案仅作为未来建议，不在本轮保留。

## 备选方案

- 直接根据测试通过切换主站：超出本轮范围且存在真实环境阻塞，不采用。
- 将测试变量整包复制到正式站：会覆盖数据归属、密钥与回调，不采用。
- 只做泛化清单：无法发现本轮已验证的支付宝验签失败及旧 Worker，不采用。

## 影响与验证

具体证据与未来执行步骤见 [上线核查记录](../v2-production-readiness-2026-11-07.md)。核对最终代码及配置与本轮开始时一致、仅新增文档；核对远端更正提交和两站部署。正式站保持既有部署；测试分支的纠正提交用于恢复原构建行为，不代表正式发布。
