# ADR 0027：V2 正式发布前核对环境差异并收紧构建边界

- 日期：2026-11-07
- 状态：准备中；尚未授权切换主站，正式环境验收存在阻塞
- 关联：ADR 0003、ADR 0007、ADR 0008

## 背景

用户已报告 V2 功能测试通过，要求准备上线并核对主站与测试环境差异。测试站的业务结果不能代替正式配置、凭据和回调的验证。当前 `vercel.json` 仅允许测试项目构建，直接合并到 `main` 会让正式项目跳过构建。

## 决策

1. 本轮只做差异核查、本地发布准备及测试分支交付，不合并或推送 `main`，不修改正式配置、数据库、Worker 或域名。
2. 构建规则保留测试项目对 `prompt-lens-V2` 的限制，增加正式项目 ID、`main` 分支、Production 环境同时匹配时才继续构建的分支。正式项目中的 V2 分支、Preview、空分支和未知项目均跳过。测试项目原有空分支恢复能力保留；实际手动发布仍须单次明确授权。
3. 正式发布必须在阻塞项解决后获得明确上线授权，先本地验证、提交并推送 GitHub，再由 Git 集成构建。根目录绑定保持测试项目；不得通过 CLI 上传或人工提升代替 Git 发布。
4. 正式数据库、用户、钱包、订单、会话密钥和已有 BYOK 解密方式保留。禁止覆盖测试库、搬运测试赠送权益、盲目执行 `db:push` 或重跑历史迁移。先比对实际结构及迁移历史，再制定有证据的变更。
5. 仅保存脱敏配置差异与验收结果，不保存密钥、密文、连接密码或会话。敏感变量不可回读时记录为未验证，不尝试绕过平台限制。
6. 上线前必须处理运行时、Worker、邮件、链接解析、商业化和存储差异；域名与第三方回调使用正式地址，测试白名单继续保留。公开样例资源需保留，禁止因清理测试环境删除。

## 备选方案

- 测试通过后直接合并：会遗漏缺失配置和旧 Worker，不采用。
- 将全部测试变量复制到正式项目：会覆盖正式数据连接、密钥、回调及访问范围，不采用。
- 删除构建限制：会扩大正式项目接收错误分支的范围，不采用。

## 影响

正式发布仍需配置补齐和验证；这次构建规则只为未来经授权的 Git 发布提供路径，不构成上线操作。核查证据、具体差异、阻塞项及回退要求见 [上线核查记录](../v2-production-readiness-2026-11-07.md)。

## 验证计划

- 用实际 shell 执行项目、分支和环境矩阵，验证允许及拒绝路径，禁止仅比较配置字符串。
- 核对远端分支 SHA、Git 来源的部署 SHA、固定测试域名与主站部署 ID；主站继续保持旧部署。
- 正式发布前补齐证据；发布后在正式域名验证登录、真实浏览器上传、链接导入、后台任务、改写、支付到账及重复回调。保留旧应用与 Worker 镜像，回退不删除新订单或账本。
