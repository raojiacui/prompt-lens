# ADR 0080：Waffo 实际汇率响应诊断与兼容

- 日期：2026-11-20
- 状态：已修复并完成测试站五种外币报价复核；未宣告外币收款验收通过。

## 背景

负责人在已登录测试站选择 USD 后，三档套餐均提示无法获取换算价格。测试库确认人民币订单已经取得 Waffo checkout_id，但没有支付成功事件或发放权益。现有汇率错误被统一捕获，运行日志无法区分查询错误和响应格式不符。

## 决策

- 2026-11-20 实际测试请求确认：USD 汇率为 `0.149853215900`，JPY 为 `23.875888148100`；两者 `expiryTime` 均为毫秒整数（例如 `1795183202000`），原实现使用 `Date.parse` 导致拒绝合法响应。解析兼容毫秒安全整数与 ISO 日期字符串，保留过期检查和最长五分钟缓存；不将秒级时间戳猜测放大。
- 在服务端记录汇率查询失败的错误类别、状态、GraphQL 通知和汇率字段形状，便于核对真实响应；不记录请求头、商户私钥、客户资料或完整异常对象。
- 继续使用真实网关汇率和原订单锁价；错误时禁止创建外币订单，不编造汇率、不静默替换为固定默认价。
- 仅通过 staging/v2 发布测试项目，保留邀请和验签，主站不变；本地针对支付、币种和配置回归验证后提交。
- 官方现行 Local Currency Pricing 文档说明，商品计价币种和用户实际扣款币种是两层。SDK 的六币种矩阵约束计价/方式组合；不能据此断言加拿大、新加坡、印尼或台湾顾客不能按本币扣款。Waffo 根据付款时 IP 自动选择支持的本币，通知仍携带计价币种，退款以原计价币种请求，由 Waffo 按原汇率退还顾客本币。该语义在后续界面和说明中明确。

## 备选方案

- 让负责人反复重填商品价格：人民币结账已通，尚无证据指向商品配置，不采用。
- 忽略有效期或缺失字段并硬编码汇率：可能错收，不采用。
- 改为后台静态外币价格：改变负责人已确认的自动换汇策略，不采用。

## 后果与验证

诊断先发布测试环境，由正常登录会话触发只读报价请求，再按真实响应修复并补回归。官方本币换算包含由买家承担的 2–4% 转换费用，产品计价展示须与最终收银台扣款相区分，不将计价币种强称为银行实际扣款币种。

回归覆盖真实 USD/JPY 汇率形状、人民币 34.90 分别换算 5.23 美元和 833 日元、有效期缓存上限，以及过期毫秒、误用秒、非整数和非法日期拒绝。上线后复核五种外币三档价格及主站部署 ID。
