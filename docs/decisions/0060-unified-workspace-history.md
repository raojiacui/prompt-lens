# ADR 0060：历史页接入 V2 分析项目和视频生成记录

- 日期：2026-11-13
- 状态：本地验证通过，待 V2 Git 集成部署核验。

## 背景

用户已有分析与视频生成任务，侧栏历史页仍显示空白。该页仅调用读取旧版 `analysis_history` 的接口；V2 分析保存于 `projects`、`project_versions`、`scene_versions`，没有写入旧表。现有视频生成历史组件只挂在生成页面中，未挂到侧栏历史页。旧历史页面还会把 HTTP 错误当成空列表。

## 决策

- 历史页提供“分析历史／生成历史”两个入口。生成历史直接复用现有组件和服务端合并查询，展示平台积分及自带 Key 生成记录、结果视频、失败及待核实状态；保留既定生产环境七天保留策略和查询状态行为。
- 分析历史读取当前账号的 V2 项目和旧版提示词，统一排序、搜索及分页；保留旧记录的收藏、备注与导出。搜索覆盖项目名称、当前版本镜头提示词及旧版记录内容，分页总数使用相同筛选，SQL 通配字符按字面搜索。
- 列表仅返回项目概要，选中后通过已有账号归属校验的项目详情接口加载当前版本全部镜头提示词；按原生成提示词整理规则复制，保持用户编辑。支持跳转分析工作区并按 URL 中的项目 ID 加载对应项目。
- 显示处理中、失败和部分完成状态。读取失败明确报错并允许刷新，避免误报“暂无记录”。列表与详情读取使用不缓存策略，未修改登录、邀请名单和凭据权限。
- 从现有数据读取，历史项目立即可见；不双写旧表、不回填数据、不迁移数据库、不重跑分析或生成任务。旧记录编辑操作仍只作用于旧表，V2 项目继续在分析工作区编辑管理。

## 备选方案与后果

把所有 V2 结果复制到旧表会重复存储且容易在用户改写后出现旧提示词，因此不采用。仅指引用户到分析页项目列表或生成页底部无法修复侧栏历史入口，故不采用。复用现有项目和生成数据保持单一事实来源，列表对两套数据分别按当前用户过滤；详情沿用现有项目归属校验。

## 验证计划

- 隔离 PostgreSQL 兼容数据库验证已有 V2 项目与旧记录可见、跨账号不可见、当前版本提示词搜索、分页总数、收藏及媒体筛选。
- 浏览器从历史入口查看镜头提示词、切换生成历史查看结果视频、重新打开对应分析项目，验证读取失败和刷新恢复；所有网络由夹具拦截，不发送推理请求。
- 执行相关历史、项目列表、凭据联调回归和本地构建；验证后独立提交并通过 V2 Git 集成部署，核对远端及部署 SHA、测试域名、正式站部署 ID。

## 本地验证结果

- 4 个测试文件、23 项测试通过。隔离数据库实际执行合并 SQL，验证 V2 与旧记录、账号隔离、搜索当前版本、筛选和分页总数。
- 浏览器挂载实际历史组件，使用隔离数据库的列表响应查看已有镜头提示词，切换生成历史查看保存的视频地址，并跳转挂载实际分析工作区加载指定项目；正常登录和余额读取使用隔离夹具。加载失败与刷新恢复验证通过，无额外请求及浏览器异常。
- `npm run build`（含类型检查）和 `git diff --check` 通过。未修改真实数据或发送推理请求；线上登录后的完整历史流程仍需用户会话验收，本地夹具结果不作为线上验收通过标记。

## 2026-11-13 发布前完整回归补充

- 完整回归发现 private-user-routes 的历史隔离用例仍断言旧 analysisHistory.findMany；统一历史已改为执行联合 SQL，因此该夹具失效。修正该既有用例，删除未再使用的旧 history/count 模拟。
- 保留真实 listAnalysisHistory，检查列表和总数两条 SQL 的旧历史与 V2 项目分支均使用登录账号，忽略请求伪造的 userId；同时验证页长 100 上限、负页码归一及未登录不执行查询。未修改产品接口或降低账号隔离要求。
- 更新后执行定向回归及完整测试；结果在发布前收尾记录中补充，不将旧夹具失败描述为用户数据已泄露。
