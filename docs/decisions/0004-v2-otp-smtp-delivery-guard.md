# ADR 0004：V2 验证码邮件发送前执行 SMTP 预检

- 状态：已接受
- 日期：2026-10-23
- 决策方：Prompt Lens 项目团队

## 背景

V2 线上测试环境的验证码接口曾返回 HTTP 200，但用户没有收到邮件。Vercel 运行日志显示，邮件任务随后在 Better Auth 的后台任务中失败，错误为 `SMTP_PORT must be a valid port number`。测试环境的 SMTP 配置从 dotenv 文件复制而来，端口值中的双引号被 Vercel 当作实际内容保存；本地 dotenv 会自动去除这些引号，因此本地测试没有暴露同一问题。

Better Auth 的邮箱验证码接口会捕获邮件回调异常并记录日志，接口仍可能返回成功。只依赖 HTTP 200 无法确认 SMTP 配置可用。

## 决策

- V2 测试项目中的整组 SMTP 变量使用去除 dotenv 外层引号后的值重新配置；
- SMTP 运行时读取统一去除首尾空格及成对的单引号或双引号；
- 端口必须完整匹配数字格式并位于 1 至 65535，防止部分解析掩盖错误配置；
- 请求发送验证码前先调用 SMTP `verify` 检查主机、端口、TLS 和认证；预检失败时返回 HTTP 503 和明确的用户提示；
- 成功的 SMTP 预检在单个运行实例内缓存五分钟，减少重复连接开销；
- Better Auth 的 `nextCookies` 插件放在插件列表末尾，确保后续认证插件产生的 Cookie 可以交给 Next.js；
- SMTP 密码等敏感值继续使用 Vercel Sensitive Environment Variable 保存，不写入代码、日志或 ADR。

## 备选方案

### 只修正 `SMTP_PORT`

同批复制的主机、账号、密码和发件地址也可能包含 dotenv 外层引号，只修端口可能让错误移动到 DNS 或认证阶段，因此不采用。

### 保持接口先返回成功，仅依靠运行日志排查

用户会持续看到“验证码已发送”，而实际发信失败。该体验会掩盖配置问题，因此不采用。

### 每次请求都重新建立一次额外的 SMTP 预检连接

能提供最及时的检查，但会增加登录延迟和 SMTP 连接数。当前采用五分钟实例级缓存，在故障可见性和连接成本之间取平衡。

## 影响

- 配置、网络或 SMTP 认证异常会在验证码页面直接显示发送失败；
- 每个新运行实例首次发送验证码时会多一次 SMTP 握手；
- 五分钟缓存期间仍存在极短的服务状态变化窗口，真正的发信错误继续写入 Vercel 运行日志；
- V2 测试环境可以继续复用已批准的 Resend SMTP 凭据，正式站配置不变。

## 验证计划

- 使用带 dotenv 外层引号的 SMTP 配置完成生产构建，确认运行时可以规范化读取；
- 模拟 SMTP 预检失败，确认接口返回 HTTP 503，且不继续调用 Better Auth 发送接口；
- 使用 V2 测试域名向白名单邮箱请求验证码，确认接口成功、Vercel 日志没有 SMTP 错误且邮件实际到达；
- 验证验证码登录后的会话 Cookie 生效；
- 部署后确认 `https://prompt-lens.cc.cd` 的部署 ID 未变化。
