# ADR 0007：从同一 R2 桶校验读取分析帧并以内联图片调用 KIE

- 状态：已采纳（待主站部署及真实用户流程验收）
- 日期：2026-10-25

## 背景

用户提供的主站 Runtime Logs 最近一小时截图有 10 条 Error、7 条 Warning。KIE 错误包含图片下载 HTTP 404（外层 400 或 524）及上游超时、503、504。外层 524 无法单独证明模型拥堵。

原流程使用签名 PUT 向 R2 桶上传帧，再把 `R2_PUBLIC_URL` 拼接的 `r2.dev` 地址发给 KIE。服务端只检查地址归属，未读取或验证对象。上传成功无法保证该公开地址能被 KIE 下载。截图证明下载路径发生 404；公开域名映射、访问策略和出错时对象是否存在尚无完整生产证据。

## 决策

1. 保留浏览器直传 R2、每次分析的独立目录和用户归属校验。权限及额度检查后，从上传所用同一桶通过认证的 GetObject 读取帧。
2. 读取过程逐块限制每帧 2 MiB，校验非空和 JPEG 文件头。5 张帧并发读取，所有帧共享 15 秒读取预算；避免累积占满 Vercel 300 秒执行时间。
3. 服务端转为 `data:image/jpeg;base64,...` 再调用 KIE，去掉 KIE 下载临时公网图片的步骤。浏览器到 Vercel 的请求继续只传地址，保持小体积入站请求。
4. 缺失或无效帧返回 400 和 `ANALYSIS_FRAME_UNAVAILABLE`，在收费模型调用前结束；存储鉴权、网络问题保留为服务端失败。
5. 保持完整分析及重试结束后再清理临时帧。未调整共享桶的 CORS、公开域名或生命周期。
6. 上游错误中的媒体 URL 和内联图片数据在输出到日志或客户端前替换为占位符，避免回显签名凭据及图片内容。重试分类见 ADR 0001。

## 备选方案与验证依据

- 仅增加重试：缺失文件不可通过重复调用恢复。
- 同桶短期签名 GET 地址：真实测试证明测试桶 PUT、对象读取和签名 GET 字节校验成功，但 KIE 图片调用两次后返回 `524: 2 times retry fail`。这不足以确认签名地址不兼容，因此不把单次结果当作根因；本轮选择已在对照测试中成功的内联图片。
- 只改公开域名：需要先核实生产桶绑定，且仍依赖 KIE 的外部下载行为。
- 内联图片：合成 JPEG 的真实 KIE 3.8 Flash 调用成功；纯文本对照也成功。由服务端从 R2 读取，可同时处理公网访问故障和对象缺失。

## 后果

- 每帧增加一次认证 GetObject，Base64 使出站数据约增大三分之一；最多 30 帧、每帧 2 MiB，内存及请求体有明确上界。浏览器入站请求不包含大图片。
- 临时帧依旧只在原本已授权的分析请求中交给 KIE，未扩展用户数据用途。
- 真正上游超时或持续过载仍可能失败；最多额外重试一次，无法保证第三方始终可用。
- 本地测试桶为 `promptlensdev`，与截图中的生产公开域名不同；测试桶成功不等同于生产验收。

## 验证计划

- 单元测试覆盖对象缺失、流式读取大小上限、JPEG 格式、共享超时、存储错误分类和媒体地址脱敏。
- 路由集成测试确认传给 KIE 的帧为内联图片，并且推理结束前不会清理临时帧。
- 使用测试桶执行签名 PUT、认证 GET、一次合成图片真实 KIE 分析，清理本次独立对象。默认测试不调用收费服务。
- 执行非 E2E 测试、类型检查和生产构建。
- 主站发布后用真实登录会话完成多帧视频分析，核查对应 Runtime Logs；取得证据前保留生产验收未完成状态。

## 已取得的验证证据

- 175 项非 E2E 单元及集成测试通过，类型检查及生产构建通过。
- 最终实现的测试桶签名上传、认证受限读取、单帧内联 KIE 调用成功。
- 使用同一合成 JPEG 作为 8 张内联图片的 KIE 调用成功；这验证多图片格式，尚未替代真实视频抽帧验收。
- 增加内联图片日志脱敏后，24 项 KIE 响应与重试测试通过。
