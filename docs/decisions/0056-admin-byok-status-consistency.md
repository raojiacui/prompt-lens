# ADR 0056：管理员的自带 Key 状态与设置凭据保持一致

- 日期：2026-11-13
- 状态：修正已实现，按 V2 测试发布流程验证。

## 背景

用户在设置中已保存无限星河 Key，分析页选择“自带 Key”仍提示未配置。只读核对测试库确认管理员账号持有一条有效启用的 Infistar 记录，首选标记为 false；该记录作为唯一来源可被既有凭据选择器正确选中。

根因是 `getVideoAnalysisEntitlement` 的管理员分支将 `hasUserApiKey` 固定为 false。设置读取与 `/api/credits/me` 对同一条记录返回了相互矛盾的状态，前端在上传及分析之前直接拦截。此前单独的供应商调用和设置保存测试未覆盖管理员身份下这条跨接口链路。

## 决策

- 管理员额度信息通过既有 `resolveApiKeyForFeature` 读取真实的自带凭据状态，取消固定 false。继续使用原凭据解密、供应商首选及仅有一家供应商时的兼容选择逻辑；不通过 Key 前缀在页面猜测、不让前端接触明文 Key。
- 管理员仍保持 admin 模式和既有平台访问权限。平台 Key 本身不算用户已保存的 Key；没有保存个人 Key 的管理员继续返回 false。普通账号、套餐、拆镜收费、来源切换及历史任务的供应商固定逻辑均沿用原规则。
- 新增跨接口回归：同一条真实加密的本地测试凭据同时经设置 GET、额度 GET 与实际凭据读取器验证，覆盖管理员 Infistar、管理员 KIE、普通账号和未配置个人 Key 的管理员。保留真实供应商选择器，不用模拟 `hasUserApiKey=true` 掩盖问题。
- 浏览器测试使用实际分析页面和实际额度 API 产生的响应，在隔离媒体与接口夹具中选择自带 Key 并点击分析，验证进入 `byok_split` 报价，且不提交确认执行。仅供应商网络、上传及报价使用隔离夹具，不关闭认证或线上功能开关。

## 备选方案与后果

直接跳过页面的 Key 检查会掩盖状态不一致，也会让未配置账号进入无效流程；在额度接口直接写死 true 会误认平台 Key。采用统一的已有凭据解析器，使管理员身份与个人 Key 配置各自独立表达。管理员额度查询增加一次现有解析调用，既有管理员异常兼容仍由该解析器负责。

## 验证计划

- 修正前新增回归真实失败于两个管理员持有 Key 的用例，普通账号和无个人 Key 管理员用例通过。
- 修正后验证设置、额度、页面报价与队列供应商固定回归；检查浏览器未再显示“请先配置”，没有触发任务确认或真实付费模型。
- 完成本地类型和构建检查、独立提交并推送 V2，核对远端 SHA、Git 部署、测试域名及正式站部署 ID。正常登录会话下的线上实际付费推理不属于本轮无费用验证结论，不标记完整供应商功能验收通过。

## 本地验证结果

- 43 项定向回归全部通过，包含实际设置读取、额度响应、凭据解密和供应商固定，以及实际分析页面的浏览器点击流程。浏览器使用额度 API 的真实计算结果，成功提交自带 Key 的 `byok_split` 报价请求，任务确认次数为零。
- TypeScript 与 Next.js 构建通过。构建保留仓库既有 lint 和本地第三方登录配置警告，未禁用认证或发布功能。
- 没有读取或输出用户明文 Key，没有发送真实供应商推理或生成请求，没有修改用户凭据、套餐或余额。
