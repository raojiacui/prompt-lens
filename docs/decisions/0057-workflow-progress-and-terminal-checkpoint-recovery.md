# ADR 0057：工作流进度使用真实检查点，完成检查点可独立收尾

- 日期：2026-11-13
- 状态：已实现，按 V2 流程验证发布。

## 背景

用户报告单镜头任务进度从 65% 自动增长至 69% 后反复回到 65%。前端每 900 毫秒人为增加 1%，任务轮询每 4 秒又根据实际 0/1 镜头重算为 65%，两套机制产生了可复现的假增长和回退。

对应 QQ 测试账号的试用任务 `daad2b91-4cad-46be-b4fd-382ba405a6d1` 使用平台 KIE。后台已将唯一镜头记录为 `ANALYSIS_INTERRUPTED`，但任务仍在 running 的完成检查点，试用预约仍 pending。日志只能确认任务中断及收尾未完成，缺少足够证据判断最初请求中断的具体原因，不能归因于 Infistar Key 或宣称供应商请求从未发生。

## 决策

- 删除旧页面定时增加百分比的逻辑；准备阶段 60%、镜头处理按已完成检查点映射到 65–95%、保存阶段 95%，不把经过时间当作已完成工作。任务接口返回真实阶段和创建时间，页面独立显示等待时长；错误时保留真实状态并停止终态任务轮询。
- 提取同一套版本汇总及结算逻辑。所有镜头已有成功或失败检查点后，收尾不再依赖重新读取供应商 Key、续期推理预约或再次调用模型。
- queued 的完成检查点可立即收尾，running 的完成检查点超过 60 秒后可由本人状态查询或既有恢复流程完成。更新时按原状态和更新时间竞争领取新的 executionId，旧执行者失去写入权限；既有事务与终态检查保证积分及试用预约只结算一次。
- 仍在推理、镜头未处理完或检查点数量不一致的任务不能走此快速收尾，不缩短它们的六分钟执行租约。正常后台处理、邀请名单、套餐与付费模型入口保持生效。
- 补充模型调用前后及执行权丢失的阶段日志，不记录 Key 或媒体内容；保存检查点零行更新时明确报告执行权丢失，避免静默假成功。

## 本次任务处理

在测试库中核对只有这一个活动工作流、cursor=1/1、成功 0、失败 1，且平台 Key 指纹匹配。先使用严格租约保护的恢复探针，因租约未过期拒绝执行，没有写入。随后仅对这个已完成失败检查点调用既有幂等失败结算函数；未重新运行推理或后台调度。

处理后真实状态为 failed，项目为 failed，chargedCredits=0，试用预约 released，该账号 trial_used=0。保留中断原因和空的失败分析，不伪造成功结果，也不新增套餐或赠送额度。临时诊断入口、导出及日志保存在忽略目录，不纳入功能代码。

## 备选方案与后果

仅把百分比限制为单调递增仍会让失败任务看起来不断推进；自动重跑未确认结果的请求可能重复产生费用；直接标记任务成功会伪造交付，均不采用。采用真实检查点和独立、可重复的收尾，处理中百分比可能停留在同一值，但已等待时长持续更新。原请求中断的具体原因仍需后续实际请求日志确认，本轮不新增付费推理来推测原因。

## 验证计划

- 浏览器模拟多次相同 0/1 响应，确认显示稳定在 65%，不随时间增长或回退；终态失败出现后停止轮询，分析只提交一次。
- 隔离数据库验证未完成推理不会被快速回收，成功结果不丢失，失败试用释放一次，过期预约或后续凭据变化不妨碍已有结果收尾，旧执行者不能提交迟到结果。
- 验证本人任务接口返回最终状态及真实开始时间，保留所有权检查；完成类型和构建检查，提交后经 V2 Git 集成发布，核对远端与部署 SHA、测试域名和正式站部署未变。

## 本地验证结果

- 52 项定向回归通过，包括实际分析页面的浏览器时钟测试、真实进度检查点计算、隔离数据库收尾与试用恢复、所有权与中间结果接口、原有调度路由。
- 浏览器经过多个轮询周期仍显示 65%，失败响应后停止轮询，初次分析提交次数为 1；成功或失败检查点的收尾测试均未重复调用模型。
- TypeScript 与 Next.js 构建通过。保留既有登录配置和 lint 警告，未修改发布功能开关。测试数据、媒体和临时恢复入口未纳入功能提交。
