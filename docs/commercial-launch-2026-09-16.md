# 商业化上线验收

更新：2026-09-16。代码已经接入购买、权益到账、报价确认、消费预留、成功结算、失败释放、订单恢复、现金退款与异常复核。**这不等于已经完成真实收款验收，当前不得对外开卖。**

## 价格与范围

| 一次性套餐 | 通用积分 | 包含改写次数 |
| --- | ---: | ---: |
| 19.90 元 | 200 | 20 |
| 59 元 | 650 | 60 |
| 129 元 | 1500 | 150 |

- 改写不另扣积分，但扣套餐包含的次数；失败释放次数。无自动续费。
- 自动拆镜按原视频总长每开始 6 秒收 1 积分：30 秒 5 分，60 秒 10 分。
- 平台 Flash 分析：拆镜费 + 成功镜头数 + ceil(成功镜头总秒数 × 0.4)。Pro：拆镜费 + 成功镜头数 × 2 + ceil(成功镜头总秒数 × 0.5)。平台全部分析失败不收拆镜费。时长按整数微秒累计，不逐镜头向上取整。
- 手动上传不收拆镜费。BYOK 手动分析不扣平台积分，BYOK 自动拆镜在拆镜资产交付后扣拆镜费，模型费用由用户 KIE 账户承担。
- 失败镜头重试复用资产，只收累计成功金额的差额；不重复收拆镜费或重复取整。
- 首发分析上限：60 秒、100 MB、20 个真实镜头。实际信息由服务器探测，不采信浏览器报价。
- 首发平台生成适配器仅 Wan 2.6 文生/单图生，720p，5 秒 95 分 / 10 秒 185 分；不支持参考视频或额外比例覆盖。其余组合不能走平台付费，BYOK 仍按原有支持范围。公开价格证据不是 KIE 实际扣费验收，`adapterVerified=false` 保留此区别。
- 旧钱包和历史订单保留，不自动折算成新积分。

## 已接入

1. 三档套餐支付宝下单，服务端金额/权益快照，稳定请求 ID 防止刷新重复下单。电脑二维码和手机链接分开处理。只有后台验签到账才发放权益。
2. 每笔购买独立批次，积分/改写按批次分配和结算；订单、余额与任务记录在 `/billing`。关闭页面不丢订单，过期付款码不被判定为付款失败。
3. 分析预览 → 选镜头/模型/付费来源 → 报价 → 确认预留 → 分步提取与分析 → 累计结算。每一步保存状态，浏览器或后台调度继续推进；未知推理结果不盲目重试。
4. 生成先报总价，多条一起确认并原子预留，各条独立结算。余额不足全部不启动；明确供应商拒绝释放，网络超时保留待核对。
5. 改写持久化请求 ID，新版本与额度结算同一事务，所选中英文和付款来源明确。
6. 未使用且无预留的整笔套餐可申请退款；先冻结对应批次权益，再请求网关。签名回调确认后结算，失败仅恢复一次，未知状态不重复提交。
7. 支付/生成主动查询、24 小时异常队列和管理员 `/billing/review`。确认未交付的长期预留可凭至少 12 字核对依据释放，保存管理员与依据。不提供随意标记到账按钮。
8. 销售多条件开关；另有默认关闭的指定用户真实验收模式，普通用户不能使用。没有设置任何真实环境开关。

## 尚未完成的外部验收

- 本地未检测到虎皮椒商户 App ID / Secret，也没有调度密钥。不要把密钥发到聊天里；填入部署平台或本地私有环境配置。
- 0010/0011/0012/0013/0014 只在隔离 PGlite 测试库应用，**尚未应用于应用数据库**。0013 会补齐管理员活跃统计依赖的 `daily_visits` 表，0014 会兼容补齐视频生成记录的 Provider 字段；迁移前必须核对完整历史，不可盲目 `db:push`。
- 未部署新版 FFmpeg Worker，未验证公网回调和后台调度。Web 请求需支持最长 300 秒；Worker 应配置资源上限并验证真实媒体探测/提取耗时。
- 未做真实支付宝付款、漏回调补单、退款，未做实际 KIE 账单和模型输出验收。
- 虎皮椒查询返回的嵌套签名和金额字段需要真实通道确认。当前只接受可验签且带准确应用/订单/金额的返回；不满足则保留待确认，绝不使用本地金额伪造验证。查询 `CD` 是取消，通知 `CD` 是退款，不能混用。
- 外部退款、已消费套餐的退款及冻结账户需人工核对。当前只提供未使用套餐整笔退款，**不支持自动部分现金退款，也不自动解冻争议账户**。上线前确认客服处理规则和响应时限。
- PGlite 是隔离单连接 PostgreSQL，不能替代目标数据库多连接并发、Worker 实媒体、部署构建和容量验收。退款通道是否支持实际商户仍以签约能力为准。

## 部署顺序

1. 确认数据库是测试还是生产，备份并保存旧钱包/订单校验统计。审查全部历史迁移，按项目迁移流程执行到 0014。0011 对既有非空新钱包采取冻结保护，不能凭空构造消费批次，需人工对账。验证旧钱包不变、`daily_visits` 可正常写入且 `video_generation.provider` 已存在后设置 `COMMERCIAL_MIGRATION_ACCEPTED=0014`。
2. 部署新版 Web 和 FFmpeg Worker，配置公网 HTTPS 站点、R2、KIE、Worker 共享密钥和虎皮椒支付宝专用凭据。通知地址 `/api/payments/webhooks/xunhupay`，返回页 `/billing`。不要混用微信应用凭据。
3. 配置 `CRON_SECRET`。Worker 额外设置相同密钥及 `COMMERCIAL_RECONCILIATION_BASE_URL` 指向 Web 的 HTTPS 根地址；它每轮结束后 60 秒再请求对账接口。也可由可信外部调度器调用 `GET /api/cron/commercial-reconciliation` 并带 Bearer 密钥，不要重复部署两个调度器。确认任务在关闭浏览器后仍可继续，再设置 `COMMERCIAL_SCHEDULER_ACCEPTED=true`。
4. 开启消费与改写开关。先用受控账号验证；确认新表存在、费用展示和 BYOK 来源正确。保持 `COMMERCIAL_SALES_ENABLED=false`。
5. 若要真实验收，明确获得付款授权后设置 `COMMERCIAL_ACCEPTANCE_ENABLED=true` 和 `COMMERCIAL_ACCEPTANCE_USER_IDS`（精确账号 ID，逗号分隔）。该模式仍要求基础设施与迁移检查通过，只跳过公开销售和真实验收标记。用户亲自扫码，最小真实套餐 19.90 元；不能暗改订单价格为 1 分。
6. 完成下面的真实验收并归档脱敏证据后，分别将 `COMMERCIAL_PAYMENT_ACCEPTANCE`、`COMMERCIAL_MODEL_ACCEPTANCE` 设为 `2026-09-14-v6`。关闭并清空验收账号模式，最后才设 `COMMERCIAL_SALES_ENABLED=true`。
7. 上线后监控预留时长、回调验签失败、对账队列、退款争议和 KIE 实际成本。停止新销售时先关销售开关，**保留回调、已付任务消费和后台结算**，不要关闭全部任务处理导致已付款用户卡住。

## 真实验收清单

- [ ] 授权用户付款后，200 积分与 20 次改写各到账一次；重复通知不多发，伪造签名/金额不符不发。

- [ ] 目标 PostgreSQL 并发确认、回调与退款竞争无负余额、无重复发放；审计流水与购买批次能复算。
