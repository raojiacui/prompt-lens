## 1. 产品定位与第一阶段目标

核心价值：将参考视频拆解成逐镜头可复用提示词，再通过做同款或 AI 改写生成新视频。付费围绕完成创作流程，而不是出售模型访问权限。

- 视频分析负责建立首次价值；做同款与改写创作承接付费使用和复购。
- 音频作为辅助能力，不单独销售套餐；剪辑不作为首发商业卖点。
- 首发采用免费试用 + 一次性积分包，不自动续费，不提供无限生成或终身无限使用。
- 国内支付已确定：虎皮椒支付宝通道，自动确认与到账。移除微信付款和人工转账购买入口。
- 本期只上线人民币、虎皮椒支付宝。海外支付、Creem、美元商品与海外定价全部暂缓；保留历史代码和订单，不作为本期交付或验收条件。
- 第一阶段验证：用户是否完成首次有价值的分析、是否愿意购买、能否成功生成、是否复购，以及每种操作的实际毛利。

## 2. 当前基础与上线阻塞项

已具备：余额与流水、分析扣费、积分包、支付订单、虎皮椒和 Creem 下单与回调基础。

本次代码检查发现：

1. 普通用户视频生成要求自带 KIE Key，禁止使用付费平台 Key；购买积分不能直接完成落地页描述的生成流程。
2. 分析先执行后结算，没有任务级预留，并发执行可能造成任务完成后余额不足。
3. 支付入账先查记录再写入；流水的支付引用只有普通索引，不能保证并发回调只到账一次。
4. 套餐范围主要是分析；权限依赖历史购买记录，不能替代余额检查和每次任务授权。
5. AI 改写没有明确平台成本边界，改写、检查和自动修正都可能产生调用费用。
6. 自带 Key 分析应走独立的单文件分析路径；目前权限依赖购买历史，需防止付费历史让 BYOK 模式错误解锁自动拆镜。

这些属于首发需要处理的问题，不代表支付生产环境已完成端到端审计。

## 3. 用户与权益

| 用户 | 可用权益 | 限制 |
| --- | --- | --- |
| 未登录访客 | 看完整示例、宣传片与价格 | 不启动付费模型调用 |
| 新注册试用 | 建议 2 次单文件短片分析，不含自动拆镜，每次最多 10 秒、1 个分析单元；每份成功结果附送 1 次改写 | 不送高成本视频生成，试用次数不每日重置 |
| 积分用户 | 分析和视频生成使用同一余额；AI改写包含在套餐权益内，不单独扣积分 | 改写的公开额度和成本预算待确认，不承诺无限使用 |
| 自带 KIE Key 用户 | 自行上传视频文件分析；视频生成 | 基础模式不含自动拆镜；可主动购买平台拆镜服务，后续分析仍使用自己的Key |
| 管理员 | 测试与补偿 | 任务仍记录成本，统计时排除内部测试收入 |

试用是独立权益，不能出现“还有免费次数，却要求先有付费积分”的情况。登录验证、上传大小、并发和频率限制共同控制试用成本。系统失败释放次数，成功后才消耗；同一请求重试不能多次占用。

### 使用模式的明确边界

- 自带 Key 基础模式：用户自行上传视频文件，作为一个分析任务处理，输出整体分析和提示词；不调用平台自动镜头检测或切片工作器，不生成自动拆镜卡片流。需要逐镜头分析时，由用户自行剪好文件后分别上传。
- 模型可能在文字里描述不同场景，这不等于平台提供自动拆镜服务。单文件抽取必要采样帧仅服务内容理解，不输出拆镜素材。
- 自带 Key 同时支持视频生成。建议不收平台推理积分；保留上传大小、并发、存储和频率限制，因为平台仍有托管成本。BYOK 不等于无限资源。
- 付费套餐内AI改写由平台承担费用，不扣积分，也不暗中扣用户KIE余额。未购买套餐的纯BYOK用户如自行选择用户Key改写，必须明确提示KIE另行收费，不能称为套餐内免费。
- 平台积分模式：可使用自动拆镜和逐镜头分析，也能生成视频。用户配置过 Key 不影响主动选择平台模式。
- 同时有余额和 Key 的账号可以选择：纯自带Key、平台全包、自带Key加平台拆镜。最后一种只扣拆镜服务积分，分析/生成仍由用户KIE账户支付；套餐内改写由平台承担；不能再扣平台分析单元费。此项修订回应用户本轮提出的付费拆镜需求。
- 前端隐藏按钮之外，拆镜 API 也需校验计费模式、额度预留与任务权限，不能直接调用接口绕过。
- 自带 Key 文件建议首发上限 60 秒/100MB、每人 1 个并发分析任务；这是平台资源建议而非用户已指定限制，可在实测后调整。

## 5. 功能计价建议

| 操作 | 建议积分 | 说明 |
| --- | --- | --- |
| 平台标准自动拆镜分析 | 5 + 3 × 分析单元数 | 每次新分析批次基础 5 分；每个镜头按每 10 秒向上取整计单元 |
| 自带Key加平台拆镜 | 暂定 5 × ceil(素材秒数/60) | 仅平台拆镜交付费，模型调用由用户KIE账户另付；限额及失败边界见第5.1节 |
| 平台标准单文件分析 | 3 × 时长单元数 | 不拆镜，无基础费；改写按套餐权益使用 |
| AI脚本改写 | 0额外积分 | 套餐包含，平台承担模型及复核成本；不单独销售标准/高质量收费档 |
| 视频生成 | 待核准 | 撤回120积分建议价；按实际模型、时长、清晰度、输入方式及音频选项核价 |
| 其他生成模型 | 单独核价后开放 | 不根据“快/普通/高质量”名称猜测成本 |
| 复制、版本切换、查看和下载已有结果 | 0 | 存储期限单独说明 |

AI改写作为套餐权益提供，不再按拆镜任务附送一次，也不独立扣积分。质量标准维持不变，不能为了免费改用不可靠模型。公开额度、重复购买叠加规则及有效期需要确认后才能销售；达到限额时提示，不静默转为收费。

分析计价示例：60 秒素材，6 个镜头、每个 10 秒，共 6 单元，23 积分，折合 ¥1.98–¥2.29。若同样一分钟含 20 个短镜头，则 65 积分，折合 ¥5.59–¥6.47。必须在深度分析前展示实际数量和报价，不宣传固定“一分钟多少钱”。

自动拆镜流程：平台全包或已确认购买拆镜服务的混合模式，且有可用额度时提供有频率/预算限制的检测预览；未选择付费拆镜的基础BYOK模式只能看示例或单文件分析。检测前可说明计价规则与费用上限，镜头数确定后确认精确价格再预留。每日预览限额与放弃任务的检测成本计入运营预算。

平台全包分析部分失败按成功单元结算；仅在至少一个单元成功时收取基础费，全部失败全部释放。系统修复失败镜头不重复收基础费；用户主动重新分析形成新报价。混合模式的拆镜交付独立结算，适用第5.1节规则。

报价锁定用户、模式、模型、参数、时长、数量、价格版本和最高扣费金额。修改参数或报价过期重新确认，不能事后加价。余额不足充值后保留原稿并重新核验报价。

### 5.1 自带Key用户单独购买拆镜服务

建议单独设收费项目，不再增加套餐或第二种积分。继续购买19.9/59/129元通用积分包，余额可用于拆镜，也能以后切换平台生成。无需购买整套平台分析，不设月费或终身拆镜权益。

首发试运营价建议：每开始60秒收5积分，折合约¥0.43–¥0.50/分钟。不含KIE模型分析、视频生成费用；付费套餐内改写由平台承担，不另扣用户Key余额。暂以60秒/100MB/最多20个镜头为单任务资源上限，均为待验证建议；超限应在模型调用前停止并说明，不静默漏镜头或追加费用。

流程：上传 → 显示拆镜服务费及用户Key另行计费说明 → 预留拆镜积分 → 检测与切片 → 交付镜头时间轴、片段和关键帧 → 结算拆镜费 → 用户选镜头并确认使用自己的Key分析。检测出超限或切片交付不完整，释放服务预留；不得当作成功交付。

拆镜成功但用户Key分析失败：保留可用拆镜资产，不退已交付的拆镜服务费；可修复Key后重试分析，不重复拆镜扣费。系统原因丢失资产时免费恢复或退服务积分。必须在付款前说明两个阶段分别结算，不能继续笼统写“分析失败全部退分”。

同一用户、同一素材及检测参数，在素材保留期内复用已付费资产不重复收费；阈值变化或素材变化如需新任务，先报价确认。资产复用严格按用户隔离，不用全站文件哈希泄露其他用户素材。

成本情景：拆镜处理预算¥0.10/分钟，加每输出镜头¥0.01交付预算。60秒6镜头共¥0.16，5积分最大包支付费后收入¥0.41882，贡献约¥0.25882、61.8%。20镜头成本¥0.30，贡献率仅28.4%；这些不是服务器实测价格。需测量CPU时间、并发、存储、流量后决定是否提高密集镜头报价或降低资源上限，不能宣传稳定高利润或无限镜头。用户KIE推理费不属于平台收入或成本。

### 6.4 改写包含在套餐后的利润计算

每包贡献 = 售价 × (1 - 实际支付费率) - 分析/生成/拆镜履约成本 - 套餐改写履约成本 - 其他可变成本。

改写预算 = 公开包含次数 × 完整链路单次成本；按100%兑现估算，不能靠用户忘记使用来保证利润。按现有Pro用量假设，每10次改写预算约¥1.4836；这不是核准成本，额外调用、思考用量及失败可能增加费用。

原有整包视频利润、视频条数和回本订单数全部撤回，因为依赖未经核准的120积分售价，且没有覆盖新的套餐改写权益。三档19.9/59/129元先保留为候选价；确认改写额度与生成真实成本后，重新核算积分数量和利润，不直接沿用旧贡献率。

### 6.5 压力测试与上线门槛

- 视频生成压力测试须在实际单价、参数及售价核准后重算；撤回以120积分售价推导的利润和206积分涨价示例。
- 若分析输入/输出实际用量是预算的3倍，则单元成本为 ¥0.10022，3积分约60.1%贡献率；须提高单元价格或调整成本，不能只靠总体充值余额掩盖。
- 支付费若为3.6%，最大包净单积分收入变 ¥0.082904。按实际行业费率替换基准，不能只按支付宝0.6%。
- 实施报价函数：积分 >= ceil(完整可变成本 / (最低净单积分收入×(1-目标贡献率)))。普通分析目标约55%，生成约60%，属于内部经营目标，不是市场事实。
- 核价样本建议：分析覆盖短长镜头、中文/英文、不同输出长度；改写覆盖正常两次调用及修正四次调用；每个开放生成参数至少验证成功扣费、失败收费/退回机制。模型价/用量任一项不明，只保留BYOK或标为暂不可用，不开放无价的平台生成。
- 采集 token usage、思考token、请求次数、KIE实际扣点及账单明细、文件大小/流量。不得读取或展示完整用户Key，也不在用户未授权时启动收费实测。

## 7. 任务扣费与失败规则

状态：报价 → 预留 → 提交 → 处理中 → 成功结算 / 确认失败释放 / 状态待核实。混合模式按拆镜服务和用户Key推理两个阶段处理；下述积分释放只针对未交付的对应平台收费项。

- 预留时原子检查可用余额并创建任务及扣费关联。同一请求 ID 只能创建一次任务和一次预留。
- 成功生成：视频地址有效且完成可播放校验，并保存交付信息后结算；分析成功须有合格的可用提示词。
- 多镜头任务逐项结算。6 个中成功 5 个，只扣对应成功部分，保留已成功成果。
- 提交被拒绝、模型明确失败、没有交付结果，释放相应预留额度。
- 请求超时、断网、用户关页面属于“状态未知”，后台按供应商任务 ID 查单，不能直接退款后盲目重提。
- 系统内部重试不额外向用户收费；状态未知时只查询或按供应商幂等能力重试，避免双任务。
- 用户再次主动生成视为新任务，重新报价。输出成功但不满意通常仍计费，提供反馈和人工异常补偿入口，不承诺无限免费重做。
- 未提交的任务允许取消并释放；已提交任务仅在供应商支持且确认取消后释放，离开页面不算取消。
- 超过模型正常时限展示“仍在确认结果”；建议超过 24 小时进入人工处理队列，不能无限冻结。人工释放后出现迟到结果，不再未经同意扣款，成本由平台记录承担。
- 平台确认失败后的退分是释放/退回积分，不等同于支付订单的现金退款。

后台任务独立于网页轮询持续收尾。余额区展示可用与处理中预留；流水包含任务、时间、扣费、退分和结果链接。

## 8. 国内支付：虎皮椒支付宝

桌面流程：选套餐 → 本地创建待支付订单 → 请求虎皮椒 → 展示官方返回的支付码与金额 → 服务端验证支付 → 事务入账 → 页面提示到账 → 返回原任务。

官方文档将 PC 二维码与手机支付链接分开返回；PC 使用返回的二维码地址，手机使用移动支付链接，不把二维码图片地址当作跳转链接。二维码文档有效期为 5 分钟，上线需按实际通道验证。

- 本地先持久化订单，固定用户、套餐快照、积分、金额、币种、支付渠道与商户订单号，再发起外部下单。
- 创建响应同样验签；不把浏览器携带的金额、到账积分、用户 ID 当作可信依据。
- 处理通知前验证签名、虎皮椒通道 appid（不是支付宝开放平台 APPID）、订单归属、金额与成功状态；只在本地事务提交成功后返回协议要求的确认内容。
- 回调、主动查单、后台补偿走同一套结算函数；数据库唯一约束与订单状态条件更新共同保证最多到账一次。
- 支付通知延迟时页面显示“正在确认付款”；浏览器查询自家订单状态，服务端受控调用虎皮椒查询，限频并缓存，避免每个页面直接高频查供应商。
- 官方查单文档建议 5–10 秒间隔，最长不超过 10 分钟。超过窗口由人工核对或通道允许的对账流程处理。
- 二维码过期后先核实旧订单，再创建新的支付尝试；过期表示不能继续展示使用，不代表已经付款的迟到通知可以丢弃。
- 刷新页面、关页、重复点击不得造成重复充值。同一未过期结账尝试尽量复用；不同真实付款订单分别到账，不吞掉重复购买。
- 用户切换账号时，不允许将订单归属迁移给当前登录人。
- “我已付款”只能触发查单，不能直接加积分。

移除前台及普通用户购买接口里的微信和人工收款选项，保留旧订单查看与对账。管理员补偿必须记录理由、关联订单和操作人。

## 9. 支付后回到创作；海外明确暂缓

本期不做 Creem、海外银行卡、美元商品、海外税费链路和海外定价。界面语言仍保留中英文，但本期实际购买仅人民币支付宝；后台不可因英文界面自动开放海外支付。

付款前保存用户拥有的项目、镜头、当前提示词、模型、参数和选择的计费模式。回跳只允许本站白名单路径，不把私密提示词放在付款 URL 里。支付成功后展示“已到账，继续生成”，用户再次确认后才预留并启动任务。

原任务若为BYOK，不因刚充值自动变成平台模式；用户可明确选择只购买拆镜服务并保留自己的Key，也可选择平台全包。

## 10. 现金退款、记录与客户体验

拟定的产品政策：重复付款、未交付且无法修复等异常进入退款处理；未消费购买积分支持提出原路退款申请，已消费部分的处理按公开条款和适用要求确认。上线前最终确定退款窗口与执行规则，本方案不将其描述为已生效政策。

- 退款按充值批次追踪实际购买积分、消耗、预留和剩余；单一总余额不足以处理部分退款。
- 先核实并冻结该笔可退余额，避免退款审核期间继续消费；供应商确认退款成功后才回收对应权益并记退款流水，失败则解除冻结。
- 虎皮椒官方有退款文档入口，具体支付宝通道是否开通自动退款、金额限制和部分退款支持必须实测；未确认前保留可审计的人工原路退款处理，不等于人工充值。
- 扣除范围只能是该订单的剩余权益，不能误扣用户其他购买的积分；拒付已消费余额进入风险处理，不无故吞掉其他订单。
- 账单页面显示购买、扣费、退分、退款与处理状态；提供订单号、收据入口和反馈入口。
- 发布清楚的积分规则、失败处理、素材保存与隐私说明；不使用“改一下就绝不侵权”“每次都保证 1:1”作为付费承诺。
- 建议试运营生成素材保留 30 天，项目文字长期保留至用户删除，具体需按成本确认。到期日与下载提示在生成前和结果页可见；供应商临时链接不能冒充 30 天平台保存。

## 11. 旧用户过渡

旧套餐有不同售价、积分面值和分析权益。新方案不得直接让旧余额突然按新单价扣除。

先导出已购订单、赠送积分和余额，核对实际购买承诺。优先方案是保留旧分析权益直到用完，新购买进入通用积分钱包；界面明确“历史分析额度”和“通用积分”，作为迁移期间的例外。

如希望一次性转换，必须逐批计算不降低原可用分析次数的补偿比例，并先向用户解释，不能统一随意乘倍数。迁移脚本需有预演、前后余额核对和回滚记录；历史支付通道仍保留对账能力。

自带 Key 的单文件分析和生成继续可用，自动拆镜可主动选择平台全包或仅付拆镜服务费的混合模式。若旧用户已购买过拆镜权益，按既有承诺过渡并说明新模式，不抹去已购价值。旧价格永久保存在订单快照，未来改价不能重写历史账单。

沿用现有余额、流水和订单，增补：

- 报价记录：用户、输入摘要、参数、金额、有效期；不暴露完整供应商密钥。

## 13. 实施顺序与上线验收

### A. 定规则与核价

确认本方案、收集模型成功和失败成本、核定三档套餐/单价、确认虎皮椒支付宝商户配置及实际行业费率。产物是有版本号的生产价目表与权益表，不是先改页面数字。

### B. 先完成账务底座

完成预留、结算、释放、支付唯一入账、退款批次和成本记录；用测试验证并发、回调重复和状态恢复。

### C. 接入产品流程

BYOK单文件分析、混合模式拆镜授权与分阶段结算、平台分析报价与镜头选择、生成两种计费模式、套餐内改写额度、余额不足充值、支付后回到原任务、账单与结果页。

### D. 支付联调

虎皮椒支付宝桌面扫码与手机跳转、验签和查单、退款核对；海外不在本期验收范围。测试环境先通过，再使用明确授权的小额真实订单验证到账、重复通知和退款，不擅自发起真实扣款。

### E. 小范围试运营

建议邀请 10–20 位已有用户，限制付费并发和模型范围。每天核对订单、余额与供应商费用。关键问题关闭后逐步开放，暂不上订阅、推广返佣和大额折扣。

必须通过的场景：

1. 同一支付通知串行或并发多次到达，只到账一次；金额/APPID/签名不符拒绝入账。
2. 支付成功关页、通知延迟、查单与通知同时到达，余额和订单一致。
3. 过期支付码后的迟到成功通知、真实重复购买均不漏记。
4. 余额只够一次时并发两次生成，仅允许一次预留；双击不会产生重复任务。
5. 提交成功但响应丢失、回调重复、任务关闭页面后完成，均能正确收尾。
6. 部分镜头失败只结算成功部分；模型拒绝与无有效结果能退分。
7. 退款处理中不能消费冻结额度；退款成功/失败事件重复处理不多扣。
8. 改写失败不扣次数，版本切换不能刷套餐改写额度；未授权用户不能查别人的账单或任务。
9. 中英文价格与订单一致，桌面和手机均能付款后回到原任务。
10. 旧积分与旧订单正确过渡；基础BYOK分析/生成使用用户Key，不能免费自动拆镜；混合模式只在预留拆镜服务费后允许拆镜，有付费历史也不能绕过。
11. 基础BYOK任务不扣平台积分；混合模式只扣平台拆镜费，不扣平台分析/生成费；两者均不静默回退平台Key，平台全包任务不扣用户KIE余额。

公开付费门槛：上述验收通过、正常购买无需人工加分、资金异常可追溯、开放模型均完成成本核价、现有用户迁移方案就绪。
